# EduNova Agent 设计

LangGraph 编排多步骤学习工作流、工具调用和质量审核；领域服务负责权限、事务、确定性计算与持久化。

## 1. 工作流

当前 `backend/app/agents/workflows.py` 定义十类工作流：

| 工作流 | 产物 | 核心步骤 |
| --- | --- | --- |
| `profile` | 学习画像 | 上下文、抽取、证据门禁、审核、应用 |
| `material_ingestion` | 资料结构 | 校验、页面提取、目录、切片、质量门禁 |
| `course_builder` | 课程 | 资料一致性、章节、知识点、先修关系、引用 |
| `material_comparison` | 资料对比 | 范围校验、证据收集、对比、审核 |
| `home_tutor` | 主页回答 | 路由、资料/网页检索、回答、审核 |
| `course_tutor` | 课程回答 | 画像、课程检索、辅导、弱点、下一行动 |
| `resource_generation` | 学习资源 | 诊断、规划、并行生成、聚合、审核 |
| `path_planning` | 学习路径 | 证据收集、确定性排序、模型规划、审核 |
| `assessment` | 练习 | 题目规划、生成、评分、诊断、路径回流 |
| `report` | 学习报告 | 练习与掌握度聚合、叙事、审核 |

报告只解释有作答与评分证据的知识点，不由局部高分推断整门课程或整体能力。模型接收课程知识点总量与证据数量；规则审核拦截已知的无依据泛化，失败保留旧报告，不替代完整语义评估。

## 2. 状态与合同

每个工作流使用类型化状态和 Pydantic Schema。模型结果必须依次经过：

```text
结构校验 → 权限与范围校验 → 证据校验 → 质量审核 → 持久化
```

公共 API 和数据库不直接依赖 Provider SDK 类型。模型、搜索、存储和工具通过项目适配层接入。

## 3. 确定性边界

以下内容不能由模型单独决定：

- 用户与课程访问权限；
- 客观题答案和确定性统计；
- 引用是否属于当前课程；
- 掌握度、弱点正式状态和课程完成条件；
- 资源版本号、事务提交和幂等性；
- 文件安全、密钥处理和日志脱敏。

模型可以参与解释、规划、题面表达和资源生成，但产物必须满足上述边界。

## 4. 工具调用

工具执行分为三个阶段：

1. 执行前：验证权限、课程范围、参数、预算和取消状态；
2. 执行中：控制超时、有限重试和并发；
3. 执行后：校验结果、脱敏、标记证据并写入上下文。

网页检索、代码验证和文件处理都遵循相同原则。工具返回不能自行声明已通过业务审核。

## 5. 后台运行

耗时工作流通过 `AIJob` 和 RQ 执行。任务与 Agent Trace 使用关联标识，但承担不同职责：

- Job 保存排队、运行、取消、失败和完成状态；
- Trace 保存学生可见的安全步骤摘要；
- 业务表保存最终产物和事实。

刷新、重试和 Worker 重启后，以数据库中的 Job 和产物状态恢复。

### 5.1 计划与资源能力边界

`services/ai_capabilities.py` 为 `path_planning`、`resource_generation` 提供内部 Pydantic 输入/结果合同。入队、重试及执行前校验参数和用户/课程范围；执行前复核课程未归档，以及知识点、任务、资源、评估、来源回答与引用的归属。资源输入复用现有 API 模型，其余能力见第 9 节。

执行沿用 LangGraph runner、队列与重试机制。写入 Job 结果前校验结构和课程范围，保留 JSON 字段及 ID 类型。`CAPABILITY_INPUT_INVALID`、`CAPABILITY_OUTPUT_INVALID` 仅返回固定安全提示，不回显输入或结果。

运行约束沿用现有分层策略：

| 层 | 约束 |
| --- | --- |
| AIJob / RQ | 排队、用户活动任务上限、有限任务重试与 worker 硬超时 |
| AgentJobContext | 两条能力使用 `ai_job_timeout_seconds` 的协作 deadline，在节点和模型取消检查点停止；超时为 `JOB_TIMEOUT`，取消保持 `cancelled` |
| 模型运行时 | 已有并发额度、单次超时、有限重试与熔断；计划保留 45 秒模型预算，资源保留类型级审核/修订限制 |

协作 deadline 不强制中断阻塞的 Provider 请求，仍由 Provider 超时与 RQ 硬超时约束。`model_task_summary` 记录用量，不是全任务 token 或费用硬额度。

能力校验不提交事务；评分、掌握度、引用审核和持久化由领域服务负责。产物与 Job 终态分别提交：结果校验失败或提交后取消不撤销产物，不提供跨事务原子回滚，也不补造批准记录或任务与资源绑定。

## 6. 质量门禁

工作流根据产物类型检查：

- Schema 完整性；
- 课程与资料引用合法性；
- 客观数字一致性；
- 个性化因素是否来自可用证据；
- 难度、教学用途和资源类型是否匹配；
- 敏感信息、提示词回显和无依据事实。

合同不合格时受控修订；仍不通过则不返回成功。

## 7. 运行模式

产物记录实际生成与审核模式，包括模型生成、确定性来源、模型加规则审核和纯规则审核。客户端据字段展示状态，不从文案推测。

## 8. Trace 与隐私

Trace 可以保存工作流、步骤、耗时、Provider/模型标识、引用数量、质量状态、降级原因和错误码。不得保存：

- 完整系统提示词；
- 完整用户资料或作答原文；
- Provider 原始响应；
- 明文 API Key、JWT 或密码；
- 模型原始推理内容。

## 9. 能力适配与运行历史

七类后台能力使用内部 Pydantic 合同，执行前复核权限，沿用 LangGraph runner。同步辅导、画像、交卷和资料对照保留领域请求/响应与 Trace，不允许通用重执行绕过评分、画像或资料确认。练习与报告生成在持久化节点前及提交前检查取消；评分仍由服务端决定。

运行历史复用领域会话/AIJob 身份，终态快照只保存元数据和固定产物引用。存储使用 SQLAlchemy JSONB、标准库摘要和课程行锁，不新增队列、检查点服务或依赖。项目维护计划分支与学习事实隔离；LangGraph checkpoint 适合恢复工作流，但 replay 可能重执行节点，因此用户回放只读快照，不调用 graph。参见 [LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence) 与 [SQLAlchemy JSON mutation tracking](https://docs.sqlalchemy.org/en/20/orm/extensions/mutable.html)。

分支复制任务蓝图，创建未批准计划，不复制成绩；重新执行创建新 AIJob，重试使用原恢复机制。操作、冲突与保留期见 API 和数据库文档。Provider 目录仅描述已安装适配器的能力，实际可用性须通过连接测试与运行校验。本层不新增外发字段、部署组件或第三方许可；质量与性能需真实 Provider 样本。

## 10. 问答上下文边界

主页与课程问答依次排列固定系统规则、已筛选的近期消息、本轮动态背景、来源和问题。会话及跨会话摘要不进入 system 消息，只作为不可信背景，不能覆盖规则或充当课程证据。边界字符转义不能完全阻止提示注入，仍需来源核验与权限检查。

同步与流式问答共用消息顺序，读取历史和构造消息不额外调用模型。动态摘要不改写固定前缀，但裁剪会改变近期历史，不保证跨轮完整前缀复用；缓存命中与费用须按供应商实际用量验证。

`AnswerContextBudget` 估算输入预算，依次移除旧历史、记忆、外部来源和多余课程来源，保留固定规则、当前问题与至少一段课程来源。最低内容仍超预算时提示重试，不静默截断。日志只记数量。

## 11. 受控三层记忆

- L1：当前会话的近期消息，受统一输入预算限制。
- L2：脱敏历史片段及来源会话/消息、主题和时间；pgvector 按同一嵌入配置召回，检查相似度并去重。
- L3：用户在设置页明确确认的目标、偏好、困难与习惯，不从模型回答自动推断；最多读取最近 8 条、合计 1200 字。

新会话首条问题即可读取 L2/L3，两者只进入不可信动态背景和统一预算，不更新评分、掌握度、权限或学习证据。

设置页支持分层分页、查看来源与时间、纠正、单条永久删除和 JSON 导出。暂停会停止读取与后台写入、保留内容；清除派生向量保留摘要；永久删除会阻断旧来源恢复。纠正使原向量失效，需手动重建后再召回。恢复开关不回填聊天，重建只处理保留摘要；清空后新对话仍可生成记忆，原始聊天保留。

记忆写入、纠正、删除和隐私变更共用 SQLAlchemy 用户行锁。向量计算在锁外执行，提交前复核账号、隐私版本、来源和删除屏障。队列只传 ID 与隐私版本；单条删除保留无正文来源标记，全量清空记录时间屏障，阻止旧任务和重建恢复内容。版本冲突返回 409。

此能力复用 SQLAlchemy/Alembic、RQ、pgvector 与 LangChain，不新增依赖或记忆平台，不增加摘要生成与长期信息抽取调用。项目负责用户确认、来源、权限、删除和预算规则；迁移平台不能消除这些隐私与事务责任。新增两张业务表及兼容字段，摘要与长期信息留在当前数据库，仅既有嵌入或问答请求按原配置使用相关片段。相似度默认 0.72，可配置；合成向量回归不代表真实召回质量。

### 11.1 可选的候选语义选择

`conversation_memory_semantic_selection_enabled` 默认开启，可显式关闭。ConversationMemoryService 复用 `ModelSettingsService`、`ModelTaskProfile`、Pydantic 与 `parse_json_object`，不新增网关、框架、表或依赖。memory_selection 合同只判定 matched/ambiguous/none 和候选白名单；所有权、来源、隐私版本、纠正及删除由业务服务控制，调用使用普通对话模型路由。

原阈值结果保留作失败回退；候选按同账号、排除当前会话、配置指纹和维度筛选 Top 5。选择器不能创造 ID 或推断跨记录覆盖。请求超时 12 秒，仅尝试一次；取消向上传递，流式返回 cancelled，不生成或保存助手回答。已发送的同步请求无法保证撤回。

调用后复核隐私版本；期间发生暂停、删除、纠正或清空时，丢弃结果及此前读取的 L3。摘要预算优先保留歧义提示，避免只剩部分历史对象。小样本质量与工程验收分别记录，合同测试不能证明大规模准确率、提示注入抵抗性或费用收益。

语义选择分别判断主题相关性和证据充分性，逐条检查对象、条件与事实依据，允许准确的同义表达。理论值不替代实测值，同题号不覆盖新条件，也不重新计算未记录的历史结果；这些领域规则受单次调用、超时、候选白名单与失败回退约束。
