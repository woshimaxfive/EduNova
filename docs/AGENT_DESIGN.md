# EduNova Agent 设计

EduNova 使用 LangGraph 表达需要多步骤状态、工具调用和质量审核的学习工作流。Agent 负责协调过程，领域服务负责权限、事务、确定性计算和持久化。

## 1. 工作流

当前 `backend/app/agents/workflows.py` 定义十类工作流：

| 工作流 | 产物 | 核心步骤 |
| --- | --- | --- |
| `profile` | 学习画像 | 上下文、抽取、证据门禁、审核、应用 |
| `material_ingestion` | 资料结构 | 校验、页面提取、目录、切片、质量门禁 |
| `course_builder` | 课程 | 资料一致性、章节、知识点、先修关系、引用 |
| `material_comparison` | 资料对比 | 范围校验、证据收集、对比、审核 |
| `home_tutor` | 主页回答 | 路由、资料/网页检索、回答、审核 |
| `course_tutor` | 课程回答 | 画像、课程检索、辅导、弱点、下一行动 |
| `resource_generation` | 学习资源 | 诊断、规划、并行生成、聚合、审核 |
| `path_planning` | 学习路径 | 证据收集、确定性排序、模型规划、审核 |
| `assessment` | 练习 | 题目规划、生成、评分、诊断、路径回流 |
| `report` | 学习报告 | 练习与掌握度聚合、叙事、审核 |

## 2. 状态与合同

每个工作流使用类型化状态和 Pydantic Schema。模型结果必须依次经过：

```text
结构校验 → 权限与范围校验 → 证据校验 → 质量审核 → 持久化
```

公共 API 和数据库不直接依赖 Provider SDK 类型。模型、搜索、存储和工具通过项目适配层接入。

## 3. 确定性边界

以下内容不能由模型单独决定：

- 用户与课程访问权限；
- 客观题答案和确定性统计；
- 引用是否属于当前课程；
- 掌握度、弱点正式状态和课程完成条件；
- 资源版本号、事务提交和幂等性；
- 文件安全、密钥处理和日志脱敏。

模型可以参与解释、规划、题面表达和资源生成，但产物必须满足上述边界。

## 4. 工具调用

工具执行分为三个阶段：

1. 执行前：验证权限、课程范围、参数、预算和取消状态；
2. 执行中：控制超时、有限重试和并发；
3. 执行后：校验结果、脱敏、标记证据并写入上下文。

网页检索、代码验证和文件处理都遵循相同原则。工具返回不能自行声明已通过业务审核。

## 5. 后台运行

耗时工作流通过 `AIJob` 和 RQ 执行。任务与 Agent Trace 使用关联标识，但承担不同职责：

- Job 保存排队、运行、取消、失败和完成状态；
- Trace 保存学生可见的安全步骤摘要；
- 业务表保存最终产物和事实。

刷新、重试和 Worker 重启后，以数据库中的 Job 和产物状态恢复。

### 5.1 计划与资源能力边界

`services/ai_capabilities.py` 为 `path_planning`、`resource_generation` 提供内部 Pydantic 输入/结果合同。入队（包括重试）和实际执行前校验参数及用户/课程范围，执行前重新确认课程未归档，并检查知识点、任务、来源资源、评估、来源回答与引用归属。资源合同复用已有 API 请求模型；其余工作流暂保持原入口。

原 LangGraph runner 继续执行，未增加队列、检查点或重试引擎。Job 结果写入前验证返回结构和课程范围，保留既有 JSON 字段及 ID 类型。错误码 `CAPABILITY_INPUT_INVALID`、`CAPABILITY_OUTPUT_INVALID` 只返回固定安全提示，不回显原始输入或结果。

运行约束沿用现有分层策略：

| 层 | 约束 |
| --- | --- |
| AIJob / RQ | 排队、用户活动任务上限、有限任务重试与 worker 硬超时 |
| AgentJobContext | 两条能力使用 `ai_job_timeout_seconds` 的协作 deadline，在节点和模型取消检查点停止；超时为 `JOB_TIMEOUT`，取消保持 `cancelled` |
| 模型运行时 | 已有并发额度、单次超时、有限重试与熔断；计划保留 45 秒模型预算，资源保留类型级审核/修订限制 |

协作 deadline 不会强制中断正在阻塞的 Provider 请求；该请求仍受 Provider 超时及 RQ 硬超时约束。调用指标沿用 `model_task_summary`，不将用量统计宣称为全任务 token/费用硬额度。

能力校验不提交事务，评分、掌握度、引用审核和产物持久化仍由领域服务负责。业务产物提交和 Job 终态提交仍是原有独立边界：结果合同失败或提交后取消不能撤销已提交产物，也不能声称实现了跨事务原子回滚。批准版本和任务—资源版本绑定不由本层补造。

## 6. 质量门禁

工作流根据产物类型检查：

- Schema 完整性；
- 课程与资料引用合法性；
- 客观数字一致性；
- 个性化因素是否来自可用证据；
- 难度、教学用途和资源类型是否匹配；
- 敏感信息、提示词回显和无依据事实。

合同问题最多进行受控修订。修订后仍不合格的产物不应写成成功结果。

## 7. 运行模式

产物记录实际生成与审核模式，例如模型生成、确定性来源、模型加规则审核或纯规则审核。客户端根据这些字段显示能力状态，不根据文案猜测模型是否参与。

## 8. Trace 与隐私

Trace 可以保存工作流、步骤、耗时、Provider/模型标识、引用数量、质量状态、降级原因和错误码。不得保存：

- 完整系统提示词；
- 完整用户资料或作答原文；
- Provider 原始响应；
- 明文 API Key、JWT 或密码；
- 模型原始推理内容。
