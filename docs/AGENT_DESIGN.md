# EduNova Agent 设计

EduNova 使用 LangGraph 表达需要多步骤状态、工具调用和质量审核的学习工作流。Agent 负责协调过程，领域服务负责权限、事务、确定性计算和持久化。

## 1. 工作流

当前 `backend/app/agents/workflows.py` 定义十类工作流：

| 工作流 | 产物 | 核心步骤 |
| --- | --- | --- |
| `profile` | 学习画像 | 上下文、抽取、证据门禁、审核、应用 |
| `material_ingestion` | 资料结构 | 校验、页面提取、目录、切片、质量门禁 |
| `course_builder` | 课程 | 资料一致性、章节、知识点、先修关系、引用 |
| `material_comparison` | 资料对比 | 范围校验、证据收集、对比、审核 |
| `home_tutor` | 主页回答 | 路由、资料/网页检索、回答、审核 |
| `course_tutor` | 课程回答 | 画像、课程检索、辅导、弱点、下一行动 |
| `resource_generation` | 学习资源 | 诊断、规划、并行生成、聚合、审核 |
| `path_planning` | 学习路径 | 证据收集、确定性排序、模型规划、审核 |
| `assessment` | 练习 | 题目规划、生成、评分、诊断、路径回流 |
| `report` | 学习报告 | 练习与掌握度聚合、叙事、审核 |

报告叙事仅解释已作答且有评分证据的知识点，不由局部高分推断整门课程或整体能力。模型接收课程知识点总量和证据数量；确定性审核补充拦截已知的无依据泛化表述，失败时保留旧报告。该检查不替代完整语义质量评估。

## 2. 状态与合同

每个工作流使用类型化状态和 Pydantic Schema。模型结果必须依次经过：

```text
结构校验 → 权限与范围校验 → 证据校验 → 质量审核 → 持久化
```

公共 API 和数据库不直接依赖 Provider SDK 类型。模型、搜索、存储和工具通过项目适配层接入。

## 3. 确定性边界

以下内容不能由模型单独决定：

- 用户与课程访问权限；
- 客观题答案和确定性统计；
- 引用是否属于当前课程；
- 掌握度、弱点正式状态和课程完成条件；
- 资源版本号、事务提交和幂等性；
- 文件安全、密钥处理和日志脱敏。

模型可以参与解释、规划、题面表达和资源生成，但产物必须满足上述边界。

## 4. 工具调用

工具执行分为三个阶段：

1. 执行前：验证权限、课程范围、参数、预算和取消状态；
2. 执行中：控制超时、有限重试和并发；
3. 执行后：校验结果、脱敏、标记证据并写入上下文。

网页检索、代码验证和文件处理都遵循相同原则。工具返回不能自行声明已通过业务审核。

## 5. 后台运行

耗时工作流通过 `AIJob` 和 RQ 执行。任务与 Agent Trace 使用关联标识，但承担不同职责：

- Job 保存排队、运行、取消、失败和完成状态；
- Trace 保存学生可见的安全步骤摘要；
- 业务表保存最终产物和事实。

刷新、重试和 Worker 重启后，以数据库中的 Job 和产物状态恢复。

### 5.1 计划与资源能力边界

`services/ai_capabilities.py` 为 `path_planning`、`resource_generation` 提供内部 Pydantic 输入/结果合同。入队（包括重试）和实际执行前校验参数及用户/课程范围，执行前重新确认课程未归档，并检查知识点、任务、来源资源、评估、来源回答与引用归属。资源合同复用已有 API 请求模型；其余工作流暂保持原入口。

原 LangGraph runner 继续执行，未增加队列、检查点或重试引擎。Job 结果写入前验证返回结构和课程范围，保留既有 JSON 字段及 ID 类型。错误码 `CAPABILITY_INPUT_INVALID`、`CAPABILITY_OUTPUT_INVALID` 只返回固定安全提示，不回显原始输入或结果。

运行约束沿用现有分层策略：

| 层 | 约束 |
| --- | --- |
| AIJob / RQ | 排队、用户活动任务上限、有限任务重试与 worker 硬超时 |
| AgentJobContext | 两条能力使用 `ai_job_timeout_seconds` 的协作 deadline，在节点和模型取消检查点停止；超时为 `JOB_TIMEOUT`，取消保持 `cancelled` |
| 模型运行时 | 已有并发额度、单次超时、有限重试与熔断；计划保留 45 秒模型预算，资源保留类型级审核/修订限制 |

协作 deadline 不会强制中断正在阻塞的 Provider 请求；该请求仍受 Provider 超时及 RQ 硬超时约束。调用指标沿用 `model_task_summary`，不将用量统计宣称为全任务 token/费用硬额度。

能力校验不提交事务，评分、掌握度、引用审核和产物持久化仍由领域服务负责。业务产物提交和 Job 终态提交仍是原有独立边界：结果合同失败或提交后取消不能撤销已提交产物，也不能声称实现了跨事务原子回滚。批准版本和任务—资源版本绑定不由本层补造。

## 6. 质量门禁

工作流根据产物类型检查：

- Schema 完整性；
- 课程与资料引用合法性；
- 客观数字一致性；
- 个性化因素是否来自可用证据；
- 难度、教学用途和资源类型是否匹配；
- 敏感信息、提示词回显和无依据事实。

合同问题最多进行受控修订。修订后仍不合格的产物不应写成成功结果。

## 7. 运行模式

产物记录实际生成与审核模式，例如模型生成、确定性来源、模型加规则审核或纯规则审核。客户端根据这些字段显示能力状态，不根据文案猜测模型是否参与。

## 8. Trace 与隐私

Trace 可以保存工作流、步骤、耗时、Provider/模型标识、引用数量、质量状态、降级原因和错误码。不得保存：

- 完整系统提示词；
- 完整用户资料或作答原文；
- Provider 原始响应；
- 明文 API Key、JWT 或密码；
- 模型原始推理内容。

## 9. 能力适配与运行历史

七类后台能力统一使用内部 Pydantic 输入/输出合同和执行前权限复核，仍由原 LangGraph runner 执行。同步辅导、画像、交卷和资料对照保留原领域请求/响应与 Trace 适配；不能通过通用重执行入口绕过评分、画像或资料确认规则。练习与报告生成在持久化节点前及提交前检查取消，评分仍由原服务端规则决定。

运行会话复用现有领域会话/AIJob 身份，终态快照仅保存元数据和固定产物引用。选择复用 SQLAlchemy JSONB、标准库摘要和既有课程行锁，不新增队列、检查点服务或依赖；项目只维护计划分支与事实隔离的领域规则。LangGraph 原生 checkpoint 适合工作流恢复，但其 replay 可能重新执行节点，因此用户历史回放只读取快照，不调用 graph。参见 [LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence) 与 [SQLAlchemy JSON mutation tracking](https://docs.sqlalchemy.org/en/20/orm/extensions/mutable.html)。

分支创建未批准的计划版本，复制任务蓝图而不复制成绩；重新执行创建新 AIJob，重试沿用原恢复机制。具体操作、冲突与保留期见 API 和数据库文档。Provider 目录沿用已安装适配器的能力声明，实际可用性仍由原连接测试和运行时验证裁决，不把静态声明当作真实模型联调结果。没有新增外发字段、部署组件或第三方许可，质量与性能仍需独立的真实 Provider 样本。

## 10. 问答上下文边界

主页和课程问答使用固定系统规则，随后是已筛选的近期对话消息，最后才是本轮动态背景、来源与当前问题。会话及跨会话摘要不进入 system 消息；它们在当前轮被标注为不可信背景，不能作为课程事实证据或覆盖系统规则。摘要边界字符会转义，但这不等于能完全阻止提示注入，原有来源核验和权限边界仍然适用。

同步和流式问答共用同一套排列，读取历史和构造消息不会额外调用模型。此设计只保证动态摘要不会改写固定消息前缀；真实缓存命中及费用取决于供应商和实际用量，不能由消息结构测试推断。上下文裁剪后近期历史仍可能变化，不保证跨轮完整前缀复用。

问答输入预算由 `AnswerContextBudget` 统一估算。固定规则和当前问题不静默截断；旧历史、记忆、外部来源和多余课程来源按顺序移除，至少保留一段课程来源。若连这一段课程来源都无法放入预算，返回可理解的重试提示。预算日志只记录数量，不保存内容。

## 11. 受控三层记忆

L1 复用当前会话的近期消息与输入预算；L2 保存脱敏历史片段、来源会话/消息、主题及时间，以已有 pgvector 按同一嵌入配置召回，并做相似度门槛和文本去重；L3 仅保存用户在设置页明确确认的学习目标、偏好、困难和习惯，不从模型回答自动推断长期事实。新会话第一条问题也能检索 L2 并读取 L3。L3 最多读取最近 8 条、合计 1200 字，仍进入不可信动态背景和统一预算，不更新评分、掌握度、权限或学习证据。

设置页支持分层分页、来源/时间、纠正、单条永久删除、JSON 导出，以及三个独立控制：暂停使用与后台写入但保留内容；清除派生向量但保留摘要；永久删除内容并阻断旧来源恢复。纠正历史摘要会使原向量失效，用户手动重建后再召回。恢复开关不自动回填历史聊天，显式重建仅处理保留摘要。清空之后的新对话仍可按开关生成新记忆，原始聊天不受记忆删除影响。

写入、纠正、删除与隐私变更复用 SQLAlchemy 用户行锁。耗时向量计算在锁外执行，提交前重新核对账号、隐私版本、来源和删除屏障。排队任务只传 ID 与隐私版本；单条删除只保留无正文的来源阻断标记，全量清空保存时间屏障，旧任务和重建不能恢复已删除内容。带版本的纠正/删除遇到并发变更返回 409。

此能力复用现有 SQLAlchemy/Alembic、RQ、pgvector 和 LangChain，不引入记忆平台或新增依赖，也不增加摘要生成和长期信息抽取的模型调用。项目维护的是用户确认、来源、权限、删除语义和预算等领域规则；第三方平台无法替代这些规则，迁移它们也不能减少此处的隐私与事务责任。新增两张小型业务表与兼容性字段；摘要/长期信息留在当前数据库，只有既有嵌入或问答请求按原配置使用相关片段。相似度默认 0.72 是可配置运行策略，合成向量回归不代表真实召回质量已验收。


### 11.1 可选的候选语义选择

默认开启、可显式关闭的`conversation_memory_semantic_selection_enabled`在ConversationMemoryService中复用已有ModelSettingsService、ModelTaskProfile和parse_json_object，不新增模型网关、框架、数据库表或依赖。新增memory_selection领域合同只决定matched/ambiguous/none及候选白名单，用户所有权、来源、隐私版本、纠正与删除仍由业务服务控制。调用走普通对话模型路由，不走资源生成模型路由。

原阈值结果单独保留作为失败回退；实验候选按相同用户/会话排除/配置指纹/维度条件取Top5。选择器不能创造ID或跨记录推断覆盖关系。取消向上传递，流式返回cancelled终态且不生成或持久化助手回答。模型请求超时12秒、一轮尝试；同步Provider调用中途不具备数据撤回保证。

暂停/删除/纠正/清空在调用返回后通过隐私版本复核使结果失效，Tutor上下文同时丢弃此前读出的L3内容。歧义提示优先保留在摘要预算内，防止旧摘要填满后只留下部分历史对象。小样本质量试验与工程验收分别记录，大规模准确率、提示注入抵抗性和费用收益仍不能由合同测试推导。

语义选择复用 `ModelSettingsService`、`ModelTaskProfile`、Pydantic 和 `parse_json_object`，将主题相关性与证据充分性分开判定。逐条检查对象对应、条件兼容以及所问事实是否有依据，允许准确的同义表达；理论期望不能代替实测值，同题号不能覆盖变化后的条件，也不能用重新计算补齐未记录的历史结果。这些领域规则由项目维护，并受单次调用、超时、候选白名单与失败回退约束。
