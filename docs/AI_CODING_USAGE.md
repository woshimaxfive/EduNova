# EduNova AI 辅助开发说明

更新时间：2026-07-28

## 0. 挑战赛优化阶段补充

V1.1 Challenge Edition 继续如实使用 OpenAI Codex 辅助完成赛题通知核对、提交材料审计、首页评委入口实现、相关测试补齐、文档同步和命令执行。人工负责选择最终亮点、确认改动范围、核对官网要求、审阅代码与文档、决定提交内容并完成最终验收。

本阶段没有新增运行时模型、第三方依赖或开源组件，许可证清单与 V1.0 冻结基线一致。Codex 不接触或写入真实 API Key，不生成共享演示账号，不把旧测试数字描述为 V1.1 重测结果；一次性浏览器验收账号及其级联数据在验证后删除。赛题中对 AI 辅助工具的限定仍按下文保留为显式待确认风险，不通过删除实际使用记录规避。

## 1. 使用范围

EduNova 在开发过程中使用 AI 辅助完成：

- 需求拆解和阶段计划。
- 代码实现和测试补齐。
- 文档同步和状态整理。
- 浏览器验收脚本辅助。
- 隐私、安全和边界审查。

实际开发辅助工具包括 OpenAI Codex。Codex 用于仓库审计、计划、代码与测试修改、文档同步和命令执行；阶段范围、产品语义、真实密钥使用、提交和最终验收由开发者控制。运行时 AI 能力与开发辅助工具分开记录：EduNova 可配置讯飞星火 X2-Flash、讯飞 Embedding，以及其他用户明确配置的 OpenAI-compatible 服务。

赛题原文写有“开发过程中使用的其他 AI 辅助工具，需选用科大讯飞相关工具”。当前仓库不删除或模糊 Codex 的实际使用记录；该句是否禁止非讯飞 AI Coding 工具，标记为赛题群待确认事项，在获得主办方答复前不宣称已经满足这一特定条款。

AI 辅助开发不等于自动接受所有输出。每个阶段必须经过测试、人工方向确认和仓库规则校验。

## 2. 人工控制点

人工必须确认：

- 阶段范围。
- 产品语义，例如画像、弱点、路径和报告的边界。
- 是否进入下一 Phase。
- 是否提交和推送。
- 开源许可证和提交材料口径。
- 真实密钥、用户资料和演示数据是否安全。

## 3. 工程约束

AI 生成或修改文件时必须遵守：

- UTF-8 无 BOM。
- 中文直接写入，不使用 `\uXXXX`。
- 不提交真实 `.env`。
- 不提交真实 API Key、JWT、用户资料和上传文件。
- 不把模型输出当成已验证事实。
- 涉及 UI 时使用真实浏览器验收。

## 4. 文档同步

AI 辅助开发必须把文档当作项目状态的一部分。代码、接口、数据库、测试、部署、安全或阶段状态变化时，应同步更新相关文档。

常见同步范围：

- `README.md`
- `docs/STATUS.md`
- `docs/PROJECT_BOARD.md`
- `docs/API.md`
- `docs/DATABASE_DESIGN.md`
- `docs/FRONTEND_ROUTING_DESIGN.md`
- `docs/TEST_PLAN.md`
- `docs/DEPLOYMENT.md`

## 5. 验收方式

AI 不能只凭“看起来实现了”宣布完成。阶段完成前至少需要：

```powershell
.\scripts\verify_encoding.ps1
.\scripts\test.ps1
git diff --check
```

涉及前端体验时，还需要 `agent-browser` 验收桌面和移动宽度。

## 6. 隐私边界

不得把以下内容发送给外部模型或写入仓库：

- 真实 API Key。
- 真实 JWT。
- 真实用户上传资料全文。
- 用户完整画像原文。
- 完整系统提示词和模型输入。
- 私人账号、手机号、邮箱、身份证件和考试资料。

必要时只使用短摘要、脱敏值和示例数据。

## 7. 贡献建议

后续贡献者可以使用 AI 辅助开发，但应遵守：

- 先读 `AGENTS.md`。
- 先确认 `docs/STATUS.md` 和 `docs/PROJECT_BOARD.md`。
- 每次只推进一个主目标。
- 保留测试和浏览器验收证据。
- 不让 AI 擅自扩大 Phase 范围。
