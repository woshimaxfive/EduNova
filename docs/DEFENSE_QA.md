# EduNova 答辩问答

更新时间：2026-07-10

## 1. 项目定位

**Q：EduNova 解决什么问题？**

A：EduNova 面向高校学生，把资料建课、课程问答、个性化资源、学习路径、练习评估、报告和导出串成一个可解释学习闭环。它不是单纯聊天助手，而是围绕课程证据和学习状态持续沉淀。

**Q：和普通大模型问答有什么区别？**

A：普通问答通常只回答当前问题。EduNova 会把资料切片、引用、画像、弱点、路径、练习和报告连接起来，并用 Agent trace、引用摘要和质量分说明结果依据。

**Q：连续追问有没有上下文？**

A：有。同一主页或课程 `session_id` 内，后端会把最近 12 条 user/assistant 消息和更早历史的安全摘要放入模型输入；课程检索和主页联网搜索也会使用最近用户问题 + 当前问题做上下文化查询。前端只展示“已参考最近 N 条会话”等计数，不展示原始历史、思维链或完整模型输入。

**Q：为什么重点演示课程空间，而不是把首页做成驾驶舱？**

A：首页 `/app` 负责轻量开始：提问、上传资料、选择资料、回到最近课程。A3 完整闭环绑定具体课程，所以 `/app/courses/:courseId` 是学习主场：回答下方串起来源、六类结构化资源、路径、练习、报告和 Agent 轨迹，生成结果可直接在课程内查看。

## 2. RAG 与防幻觉

**Q：如何减少幻觉？**

A：课程空间优先在当前用户课程资料中检索引用。回答、资源、报告和导出都只能使用安全摘要和证据引用。资料不足时显示依据不足或低依据状态，不伪造引用。

**Q：没有 embedding 服务怎么办？**

A：系统支持 OpenAI-compatible embeddings。真实外部向量按用户课程、来源和模型隔离，通过 pgvector cosine SQL 召回并与中文关键词合并；未配置或 Provider 失败时只走明确标记的关键词 fallback，`local-hash-1536` 不再冒充语义命中。

## 3. 多智能体

**Q：多智能体是否只是概念？**

A：不是。当前六条主链路已经真接管：`HomeTutorGraph`、`CourseTutorGraph`、`ResourceGenerationGraph`、`PathPlanningGraph`、`AssessmentGraph` 和 `ReportGraph`。每个节点记录真实耗时和白名单 metadata，生成型流程都有规则与可选模型 Review/Repair；模型不可用时明确标记 `rules_only`。画像、资料建课/对比、冲刺和导出仍是普通服务，认证、设置、Dashboard 不伪装成 Agent。

### 资源里的“多模态”是否只是文本换皮？

A：新资源不是统一 Markdown。思维导图使用 Markmap 画布，练习题可交互作答，代码实操通过受限 Pyodide Worker 在浏览器运行，PPT 有结构化页面预览并可异步下载真实 `.pptx`，动画图解按 Mermaid 场景播放。动画图解不是生成视频，项目不会把它包装成视频能力。

### 浏览器代码执行是否安全？

A：不执行服务端代码。Python 在独立 Web Worker 的 Pyodide 中运行，前端预检和 Python AST 双重限制导入、网络、文件、JS 互操作和动态执行，运行超过 5 秒会直接终止 Worker，输出限制为 20 KB。它用于受审核的教学示例，不是通用在线判题沙箱。

**Q：为什么不用模型直接生成全部内容？**

A：比赛演示和开源部署需要稳定可复现。EduNova 采用确定性可用稿优先，模型只做增强；弱模型、无模型或模型失败时仍能生成可读、可练、可复用的资源。

## 4. 学习画像和弱点

**Q：每门课都有一份画像吗？**

A：没有。用户级长期画像只有一份，保存专业背景、学习目标、认知风格等稳定信息。课程差异通过课程级学习状态、弱点队列、掌握度、路径和资料证据表达。

**Q：课程问答里的弱点会自动确诊吗？**

A：不会。课程问答只生成 `pending` 候选复习项。学生确认后才进入 `confirmed` 或 `reviewing`，学习路径也只消费已确认或复习中的弱点。

## 5. 练习和报告

**Q：练习批改是否依赖大模型？**

A：客观题和简答题数字分数始终由规则决定，模型不得修改。`AssessmentGraph` 可增强题目并生成错因、缺失概念和复习动作；模型不可用时保留完整规则题稿和诊断。错题精确关联 `PracticeAnswer`，同知识点合并弱点，并只重排用户已建立的路径。

**Q：报告从哪里来？**

A：`ReportGraph` 聚合当前课程最近 5 次已完成练习、掌握度、弱点、当前路径和资源。分数、数量和趋势由规则计算，模型只生成总结与下一步建议；模型失败仍保存可用规则报告。报告由用户主动生成，导出流程继续支持 Markdown、PDF 和 DOCX。

## 6. 部署和开源

**Q：如何一键部署？**

A：使用 Docker Compose 启动 PostgreSQL、Redis、backend、frontend 和 Nginx，统一入口默认是 `http://127.0.0.1:8080`。

**Q：开源时如何处理密钥？**

A：仓库只提交 `.env.example`，真实 `.env` 被忽略。用户 API Key 加密保存，日志、trace、报告和导出不能包含明文 Key。

## 7. 演示模式

**Q：为什么不做共享 demo 账号 reset？**

A：当前快速演示走注册页“带一个示例课程开始”。这种方式能保证每个评审或试用者都有自己的隔离数据，不会共享可写学习记录。独立 demo reset 后续可作为增强，不是当前主线。

## 8. 当前限制

**Q：现在最主要的限制是什么？**

A：OCR、扫描件、旧版 DOC/PPT、资料对比联动冲刺，以及其余学习流程的真实 Graph 接管还没有做。Phase 14 已完成错题证据、已有路径重排、报告趋势和隔离 Docker E2E。当前版本是可运行学习闭环，不是完整商业产品。

**Q：下一步怎么打磨？**

A：Phase 14 后继续做 Verification and Hardening：扩展六 Graph 的失败分支验收、打磨轨迹和移动端体验，并逐步补剩余 Graph、深度解析和资料对比联动。
