# EduNova 项目看板

更新时间：2026-07-10

## 1. 看板定位

本文档只记录“接下来怎么推进”。

当前已完成能力的完整说明放在 [STATUS.md](STATUS.md)。
接口、数据库、测试、部署和 UI 细节分别放在对应专业文档中，不再全部堆到看板里。

## 2. 当前原则

EduNova 坚持“基础不牢，地动山摇”的开发原则。

开发优先级：

```text
需求 -> 架构 -> API -> 数据库 -> 测试 -> 安全 -> 工程骨架 -> 功能实现
```

执行要求：

- 学生端优先。
- 每一轮只推进一个主目标。
- 实现、测试、文档同步更新。
- 不提交真实密钥和用户资料。
- 涉及前端体验时必须做真实浏览器验收。

## 7. 风险清单

| 风险 | 等级 | 应对 |
| --- | --- | --- |
| 功能范围继续膨胀 | 高 | 每轮只推进一个主目标，未进入本轮的能力写入后续计划 |
| 上传资料解析不稳定 | 高 | 已支持 PDF/DOCX/PPTX 文本抽取；OCR、旧版 Office 和扫描件继续明确不支持，不伪装解析 |
| 模型 API 不稳定 | 高 | 保留服务器兜底、个人配置、连接测试和未配置提示 |
| 多智能体变成空概念 | 中 | 学习闭环 Graph 必须落 `agent_run_logs`、`agent_trace_id`、引用、ReviewAgent 结果和质量分；模型失败时仍保留可用稿 |
| RAG 没有证据链 | 中 | 已完成引用持久化和混合检索，后续资源生成继续强制引用 |
| 前端退化成后台系统 | 高 | 继续遵守 `UI_UX_DESIGN.md`，主页保持 AI 对话入口 |
| 单人开发时间不足 | 高 | 每天保持可运行版本，先主链路后增强 |
| API Key 泄露 | 高 | `.env` 忽略、Key 加密、日志脱敏、提交前检查 |
| 文档和代码不一致 | 中 | 每个阶段完成时同步专业文档和状态文档 |

## 8. 每日工作规则

每天开始：

```text
1. 查看本看板 P0/P1。
2. 查看 git status。
3. 确认当天只推进一个主目标。
4. 先明确测试与验收标准。
5. 检查相关文档是否需要同步更新。
```

每天结束：

```text
1. 运行必要测试和编码检查。
2. 更新 STATUS 和 PROJECT_BOARD。
3. 记录已完成内容和未解决问题。
4. 提交一个清晰 commit。
5. 保证下一天能接着做。
```

## 9. 完成定义

一个任务只有同时满足以下条件才算完成：

1. 功能或文档已经落到文件。
2. 相关测试或检查已经运行。
3. 没有违反 UTF-8 无 BOM、中文不转义规则。
4. 没有提交真实密钥、JWT 或用户资料。
5. 和需求规格不冲突。
6. 相关文档已经同步更新。
7. Git 状态清楚，稳定阶段已提交并推送。
8. 涉及前端 UI、交互、路由、响应式或用户流程时，优先使用 `agent-browser` 做真实浏览器验收；Codex 内置浏览器用于补充可见确认或兜底。
