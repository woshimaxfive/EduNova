## 签名与发布状态

可信 Authenticode 签名是推荐的分发信任措施，不是 GitHub 创建草稿或预发布的统一硬性要求。未签名时必须明确披露；如之后签名，重新计算哈希并验收签名后的文件。签名不能替代第三方分发材料。

正式候选尚未上传。上传前提交本次模型选择和分发记录，令草稿指向该提交，并回读 tag、目标 SHA、Draft 状态、附件名称、大小和 SHA-256。仓库可见性保持不变。

## 手工验收步骤（有条件后执行）

1. 在没有项目源码和开发服务的 Windows x64 上核对哈希、安装、首次启动和注册。
2. 配置本人模型服务，上传真实资料并完成建课、练习反馈、课程对话和导出。
3. 测试麦克风拒绝/允许、录音/取消、中文识别与朗读；人工确认保存、取消和覆盖提示。
4. 关闭并重启，确认账号和学习记录保留；卸载后重装，确认用户数据保留。
5. 记录系统版本、安装器哈希、操作结果和脱敏日志；失败项修复后复测。
