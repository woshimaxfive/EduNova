## 2. 项目背景

高校学生在自主学习中常见问题包括：

1. 课程资料分散，课件、讲义、电子书、试题之间缺少统一组织。
2. 学生基础不同，但学习资源通常是一套标准内容。
3. 传统学习工具只能提供搜索或聊天，缺少持续画像、路径规划和效果评估。
4. 大模型生成内容容易缺乏引用来源，学生难以判断可信度。
5. 期末复习时，学生需要快速从课件和历年题中提炼重点。

EduNova 面向高校学生，构建一个 AI 个性化学习空间。它以“人工智能导论”为内置课程，同时支持用户上传资料自动建课，通过多智能体协作生成个性化资源、学习路径、辅导答疑和学习报告。

## 3. 用户与场景

### 3.1 核心用户

第一版唯一核心用户是学生。

学生可以：

- 注册并登录系统。
- 通过对话生成个人学习画像。
- 学习内置“人工智能导论”课程。
- 上传自己的课件、讲义、电子书和试题，生成个人课程。
- 生成个性化学习资源。
- 按学习路径完成任务。
- 向 AI 辅导助手提问。
- 做练习并查看评估报告。
- 导出自己的学习档案。

### 3.2 轻量维护角色

系统保留 `admin` 角色字段，用于后续管理知识库、查看系统配置和维护演示数据。第一版不建设完整后台，不做复杂运营能力。

### 3.3 典型使用场景

| 场景 | 用户目标 | 系统能力 |
| --- | --- | --- |
| 新用户入门 | 快速建立学习画像 | 对话式画像抽取 |
| 学习内置课程 | 学习人工智能导论 | 内置课程知识库与路径 |
| 上传课件 | 把老师 PPT 变成可学习课程 | 上传资料自动建课 |
| 学习薄弱知识点 | 获得适合自己的讲解和练习 | 多智能体资源生成 |
| 遇到问题 | 获得有引用的答疑 | RAG 智能辅导 |
| 期末冲刺 | 根据课件和试题快速复习 | 资料对比与冲刺计划 |
| 复盘学习 | 看清薄弱点和下一步 | 学习报告与复习队列 |

## 4. 范围边界

### 4.1 第一版必须完成

1. 学生注册、登录、退出和访问保护。
2. 学生 AI 学习空间。
3. 对话式 8 维学习画像。
4. 内置人工智能导论课程包。
5. 上传 PDF、PPTX、DOCX、Markdown、TXT 自动建课。
6. RAG 检索与引用来源。
7. 多智能体协作流程和 Agent 轨迹。
8. 至少 5 类个性化资源生成。
9. 个性化学习路径。
10. 知识点掌握地图和薄弱点复习队列。
11. AI 辅导问答，包含资料不足提示。
12. 练习、批改、评估报告。
13. 期末冲刺模式和资料对比。
14. Markdown 学习档案导出。
15. 演示模式。
16. Docker Compose 部署。
17. 开源合规、部署、测试、答辩相关文档。

### 4.2 第一版明确不做

1. 完整教师端。
2. 班级管理和作业发布。
3. 家长端。
4. 支付、课程购买、商业运营。
5. 手机 App 或小程序。
6. 扫描版 PDF OCR。
7. 图片题目 OCR。
8. 视频文件解析。
9. 真实教学视频生成。
10. 复杂权限后台。

这些能力可以作为后续路线图，但不能影响第一版主线交付。

## 5. 功能需求

### FR-001 用户注册登录

系统应支持学生使用邮箱和密码注册、登录、退出。

验收标准：

- 用户可以注册新账号。
- 重复邮箱注册返回明确错误。
- 登录成功后返回访问令牌。
- 未登录用户无法访问学生 AI 学习空间。
- 密码加密存储，不能明文保存。
- 登录页必须包含普通登录和注册入口，不提供共享“演示学生”按钮。
- 注册页必须支持空白开始或带“人工智能导论”示例课程开始；示例课程进入当前用户空间，不能复用共享演示账号数据。
- 注册成功后进入首次进入引导或 AI 学习空间。
- 路由保护行为符合 [FRONTEND_ROUTING_DESIGN.md](FRONTEND_ROUTING_DESIGN.md)。

### FR-002 AI 学习空间

系统应为学生提供统一 AI 学习空间，并以 AI 学习对话作为首页主入口。主页负责承载通用历史对话、资料选择、上传资料、生成课程和最近课程入口；课程内页面再承载课程资料、学习路径、练习、资源、AI 辅导和证据解释。第一版前端不得以固定左侧后台菜单、学习管理后台或卡片堆作为主体验。

验收标准：

- 首屏采用 ChatGPT 式贴边可收起侧栏和中心轻量输入框，突出“嗨，同学，准备好一起学习了吗？”的亲和入口；贴边侧栏承载主页历史、新建对话、资料库、资源工坊、个人资料、设置和退出登录；首次提问后进入主页对话态，输入区移动到下方。
- 主页默认不进入某一门课程，不强行展示当前课程进度。
- 主页支持独立全局历史对话；普通应用路由继续显示这批主页历史，不因为进入资料库或设置而消失；主页对话可以保留在主页，也可以移入某一课程。
- 课程内页面拥有独立历史对话、课程资料、引用来源、学习路径、练习和生成资源。
- 首页下方轻量展示最近课程或最近学习空间，不做大面积课程卡片墙。
- 资料库独立于课程，采用文件库式管理；资料类型按文档、图片等可感知文件类型划分，不把“课程内置”当作资料类型；资料默认不作为主页对话参考，学生点选后才高亮并加入本次参考，也可以加入已有课程或生成新课程。
- 生成课程以完整浮层或上层任务页面呈现，包含选择资料、填写课程名称、识别章节知识点、生成路径和进入课程。
- 登录、注册、注册 starter mode、首次进入引导和受保护路由已经设计清楚，且不会退化为后台系统入口。
- 学生可以通过主输入框发起上传资料文件、选择资料、生成课程、联网搜索、深度思考、语音输入、基于资料问答和保存回答；第一版前端实现工具位和本地演示态，真实能力按后续阶段接入。
- 主输入框使用 Enter 发送、Shift+Enter 换行。
- 引用来源、学习路径建议、联网来源和 Agent 过程显示在 AI 回答下方，并支持展开查看。

当前实现状态：

- Phase 3 已实现前端静态/半静态 AI 学习对话主页、课程空间壳子和学生端核心页面骨架，首屏包含贴边可收起主页侧栏、历史对话、侧栏账号入口、中心 AI 学习入口、输入区资料库浮层入口、文件上传入口、发送后主页对话态、底部学习输入区、最近学习轻量列表、克制背景信号线和从资料生成课程浮层；课程空间包含课程内对话、今日任务、知识画布、AI 辅导/练习/报告行动入口、资源工坊、引用来源和 Agent 轨迹；资料库已调整为文件库式页面，资源工坊、学习画像、AI 辅导、练习、报告和设置页面已具备可扩展工作区结构。
- 现有学习画布、AI 命令栏、资源输出区、证据层和 Agent 轨迹实现保留为课程内页面或后续可视化素材，不再作为首页最终方案。
- 登录、注册、注册 starter mode、首次进入引导和受保护路由已有前端实现与测试；登录页不再提供共享演示学生入口。
- 前端已补齐上传建课状态轨道、空状态、加载状态、错误恢复、低依据提示和 Demo fallback 标记。
- 前端 API 合同模块已按 `docs/API.md` 拆分，默认基础路径 `/api/v1`。
- 当前主页会话、资料、最近课程、课程空间、画像、AI 回答引用、练习反馈、报告、设置、资源和 Agent 轨迹使用前端样例数据，真实业务数据和交互在后续阶段接入。
- P3.7 已把核心按钮从空点击补成本地演示态反馈：主页发送、上传资料文件、选择资料、联网搜索、深度思考、生成课程，课程回答引用来源、学习路径、Agent 过程，知识画布节点详情，AI 辅导模式切换，练习提交，资料库查看引用，报告导出和设置保存均有可见反馈。
- P3.7 不代表真实 AI、真实上传、真实联网搜索、真实语音输入、真实导出或真实设置持久化已经完成；这些仍按后续 Phase 4 以后接入真实 API、任务队列和数据表。
- P3.9 已把资料库、课程空间、资源工坊、画像、AI 辅导、练习、报告和设置统一到贴边工作区侧栏外壳，避免普通路由保留旧顶部导航导致体验割裂；普通路由显示主页全局历史，课程空间显示课程内历史。
- P3.11 已把前端本地功能闭环补齐到“可用骨架”：课程内提问可发送并进入课程历史，资源工坊可按知识点和资源类型生成本地队列与输出，学习画像可编辑目标和追加画像证据，练习提交后显示批改态，报告导出显示准备态，设置表单可保存，侧栏 fallback 和命令栏均有可见反馈。
- P3.11 仍不代表真实 AI、真实资源生成、真实报告文件、真实上传持久化或真实设置持久化已经完成；后续接 API 时必须复用当前前端状态与页面结构，不回退到后台式管理界面。

### FR-003 对话式学习画像

系统应通过自然语言对话自动构建学生画像，画像不少于 6 个维度。EduNova 第一版使用 8 个维度。

画像维度：

1. 专业背景。
2. 知识基础。
3. 学习目标。
4. 认知风格。
5. 学习偏好。
6. 薄弱点。
7. 学习节奏。
8. 动机与兴趣。

验收标准：

- 学生输入一段自我描述后，系统能生成 8 维画像。
- 画像更新会生成画像事件。
- 画像事件包含变化原因和证据来源。
- 学生能在前端查看画像和更新时间。

### FR-004 内置课程

系统应内置一门完整高校课程作为初始知识库，第一版课程为“人工智能导论”。

验收标准：

- 课程包含章节、知识点、基础题目和学习材料。
- 知识点之间支持先修关系。
- 学生无需上传资料也能体验主流程。
- 内置课程可用于 RAG 检索和资源生成。

### FR-005 上传资料自动建课

系统应支持学生上传学习资料，并自动生成个人课程。

支持格式：

- PDF。
- PPTX。
- DOCX。
- Markdown。
- TXT。

验收标准：

- 上传后能显示解析进度。
- 系统能提取文本。
- 系统能生成课程名、课程摘要、章节和知识点。
- 系统能生成知识切片并写入知识库。
- 系统能为新课程生成初始学习路径。
- 解析失败时给出可理解错误信息。

### FR-006 RAG 检索与引用

系统应基于课程资料进行检索增强生成。

验收标准：

- 检索结果包含知识片段、来源材料、章节或页码。
- AI 回答至少显示 1 条引用来源。
- 资料不足时，系统明确提示依据不足。
- 通用知识补充必须与课程资料结论区分。

### FR-007 多智能体协作

系统应体现多智能体架构，而不是单次普通大模型调用。

核心 Agent：

- ProfileAgent。
- DiagnosisAgent。
- CourseBuilderAgent。
- RetrieverAgent。
- ResourceAgent。
- PathAgent。
- TutorAgent。
- AssessmentAgent。
- ReviewAgent。

验收标准：

- 一次资源生成至少记录 4 个 Agent 步骤。
- 每次任务有 `trace_id`。
- 前端能展示 Agent 轨迹。
- Agent 日志包含状态、耗时、输入摘要、输出摘要。

### FR-008 个性化资源生成

系统应根据学生画像、课程内容和薄弱点生成至少 5 类资源。

资源类型：

1. 讲解文档。
2. 思维导图。
3. 练习题。
4. 代码实操案例。
5. PPT 大纲或视频脚本。

验收标准：

- 用户能选择课程和知识点生成资源。
- 资源内容体现学生画像差异。
- 每个资源保存引用来源。
- 每个资源有审核状态和可信度。
- 前端在 资源输出区或结构化详情视图展示资源，避免首页资源卡片墙。

### FR-009 个性化学习路径

系统应根据画像、知识点、掌握度和薄弱点生成学习路径。

验收标准：

- 学习路径包含阶段、任务和推荐资源。
- 每个任务有推荐理由。
- 学生可以标记任务完成。
- 路径会根据评估结果调整。
- 支持 3、7、14 天冲刺计划。

### FR-010 掌握度地图与薄弱点复习

系统应展示知识点掌握状态，并把错题转化为复习任务。

验收标准：

- 知识点状态包含未学习、学习中、已掌握、薄弱、推荐复习。
- 错题会影响对应知识点掌握度。
- 系统能根据先修关系追溯前置薄弱点。
- 前端展示最需要复习的 3 个知识点及原因。

### FR-011 AI 智能辅导

系统应提供基于课程知识库和学生画像的 AI 答疑。

验收标准：

- 学生可以在课程上下文中提问。
- 回答包含引用来源。
- 支持普通解释模式和苏格拉底追问模式。
- 对资料不足问题给出明确边界。
- 对话记录可保存并回看。

### FR-012 练习与学习评估

系统应提供练习、批改和学习效果评估。

验收标准：

- 系统能生成或读取题目。
- 学生能提交答案。
- 系统能给出批改结果和解析。
- 评估报告包含得分、掌握度、薄弱点和下一步建议。
- 报告包含证据来源。

### FR-013 资料对比与考点提炼

系统应支持对多份课程资料、复习资料和试题进行对比。

验收标准：

- 能提取重复出现的高频概念。
- 能识别试题中出现但课件讲得较少的知识点。
- 能给出疑似考试重点。
- 能给出优先复习顺序。
- 输出包含引用来源。

### FR-014 演示模式

系统应提供稳定演示模式。

验收标准：

- 后续可提供独立演示模式或演示数据重置能力，但不能通过登录页共享演示学生按钮进入。
- 快速体验优先通过注册时选择“带一个示例课程开始”进入当前用户空间。
- 可以重置演示数据。
- 模型不可用时可使用明确标记的 fallback 数据。
- fallback 内容不能伪装成真实实时生成。
- 主演示流程可以稳定走通。
- Demo 进入学习空间后必须显示演示标识，fallback 内容必须明确标注。

### FR-015 学习档案导出

系统应支持学生导出 Markdown 学习档案。

验收标准：

- 导出内容包含画像、路径、资源、错题、报告、引用来源和 Agent 轨迹。
- 导出文件可下载。
- 导出过程有状态记录。

## 6. 非功能需求

### NFR-001 可用性

- 主要页面交互清晰。
- 前端体验遵守 [UI_UX_DESIGN.md](UI_UX_DESIGN.md)，以 AI 学习空间为主，不做普通教育后台。
- 长任务必须显示进度。
- 错误信息要告诉用户原因和下一步。
- 页面不应出现明显重叠、溢出或空白等待。
- 页面上的主要按钮不应长期保持空点击；未接真实 API 的能力必须有清楚的演示态反馈或禁用说明。
- 背景动效必须克制，不影响文字可读性和核心学习操作。

### NFR-002 可靠性

- 演示模式保证关键演示流程可复现。
- 外部模型失败时，系统要给出降级提示。
- 上传解析失败不能影响用户其他课程数据。

### NFR-003 安全与隐私

- 密码加密存储。
- API Key 不写入日志。
- 用户数据按 `user_id` 隔离。
- 课程数据按 `course_id` 隔离。
- 上传文件不可被其他用户直接访问。
- 提示词注入不能泄露系统配置。

### NFR-004 可解释性

- AI 输出需要引用来源。
- 关键推荐需要理由。
- 画像变化需要证据。
- Agent 执行过程可查看。

### NFR-005 可部署性

- 项目应支持 Docker Compose 启动。
- `.env.example` 提供配置示例。
- README 和部署文档能指导新用户启动系统。

### NFR-006 开源合规

- 标注参考项目名称、来源和许可证。
- 不提交真实密钥和个人隐私文件。
- 明确自主开发与参考借鉴边界。

### NFR-007 编码规范

- 所有文本文件使用 UTF-8 无 BOM。
- 禁止 UTF-16、GBK。
- 中文直接写入，不使用 `\uXXXX`。
- 提交前运行编码检查脚本。

## 8. 验收口径

EduNova 第一版只有在满足以下条件时，才能认为达到提交基线：

1. 浏览器中能完整跑通主演示链路。
2. 内置人工智能导论课程可正常学习。
3. 至少一种用户上传资料能自动建课成功，目标覆盖 5 种格式。
4. 至少生成 5 类个性化资源。
5. AI 输出包含引用、审核状态和 Agent 轨迹。
6. 学习路径、练习、评估和复习队列能形成闭环。
7. 演示模式能稳定演示。
8. Docker Compose 能启动核心服务。
9. P0、P1 缺陷清零。
10. 文档、PPT、视频和提交包完整。
