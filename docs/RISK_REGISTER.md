# EduNova 风险登记册

日期：2026-07-01

## 1. 文档目的

本文档记录 EduNova Phase 0A 起需要持续跟踪的项目风险。风险登记册用于项目看板、测试计划、答辩准备和每日开发复盘，重点覆盖范围、进度、AI 稳定性、资料上传、RAG、多智能体、前端体验、部署、安全、文档和开源合规。

风险等级说明：

- 高：可能直接影响比赛交付、主链路演示或开源安全。
- 中：可能影响体验、稳定性或开发效率，需要在迭代中主动控制。
- 低：影响范围有限，通过常规复核即可控制。

## 3. 重点风险处置细则

### R-01 范围膨胀

EduNova 第一版的主线是学生个人学习闭环。任何偏离该主线的功能都需要回答三个问题：是否服务比赛演示、是否支撑核心验收、是否能在当前周期稳定完成。不能同时满足时，不进入当前阶段。

控制动作：

- 需求规格作为范围基线。
- 项目看板只放当前阶段可交付任务。
- 对新增想法记录来源、收益和成本，由项目负责人决定是否进入后续版本。

### R-02 时间不足

时间风险通常来自“核心链路未完成但外围功能继续增加”。必须以可演示闭环为优先级排序。

控制动作：

- 每日检查注册登录、课程、上传、RAG、Agent、路径、练习、报告、Demo Mode 和 Docker 的完成状态。
- 优先修复会阻断演示脚本的问题。
- 对非主链路能力采用降级版本，保证答辩时能清楚解释。

### R-03 模型不稳定

AI 能力是项目亮点，也是最大不确定性来源。模型不稳定时，系统要表现为“可解释的降级”，而不是页面卡死或生成虚假内容。

控制动作：

- 所有模型调用设置超时、重试次数和失败原因。
- 结构化输出通过 JSON Schema 或等价校验层检查。
- 模型失败时返回人工可读错误和重试入口。
- Demo Mode 提供稳定演示响应，便于离线答辩。

### R-04 上传解析失败

上传资料自动建课是关键能力。解析失败会直接破坏“学生上传资料形成个人课程”的主线。

控制动作：

- 每种支持格式至少保留一个小型演示样例。
- 后端记录解析阶段、页数、字符数、分块数和错误类型。
- 前端展示上传、解析、建课、索引和可学习状态。
- 对解析失败的文件给出重新上传或转换格式建议。

### R-05 RAG 无引用

RAG 没有引用会削弱可信度，也会影响赛题中“可解释学习资源”的展示效果。

控制动作：

- RAG 返回结构必须包含答案、引用列表和资料不足标记。
- 引用列表至少包含资料名称、位置、摘要和分块标识。
- 前端将引用放在答案附近，便于学生核对。
- 评测用例覆盖“有资料命中”和“资料不足”两类场景。

### R-06 多智能体空心化

多智能体不能只停留在名称上，需要体现分工、协作、审查和轨迹。

控制动作：

- 每个 Agent 有固定职责和输入输出边界。
- Agent 轨迹展示任务状态、关键输入摘要、输出摘要和 ReviewAgent 结论。
- 失败时记录失败节点，允许用户重试或降级生成。

### R-07 前端体验不足

前端是答辩和演示的第一感知。体验不足会让已经完成的后端和 AI 能力难以被理解。

控制动作：

- 首页直接进入 AI 学习空间，不做空泛展示页。
- 首屏采用 AI 对话主页：贴边可收起历史侧栏、侧栏账号入口、中心轻量输入、发送后主页对话态、底部输入区、输入区资料库浮层入口、文件上传入口、最近学习轻量列表和生成课程浮层入口。
- 学习画布、Studio、证据层和 Agent 轨迹进入课程空间或 AI 回答下方的可展开区域，不在首页堆满。
- 不采用固定左侧后台菜单、指标卡片堆和普通管理系统布局。
- 上传建课、RAG 问答、学习路径和练习评估都有完整状态反馈。
- 引用、Agent 轨迹和掌握度地图使用清晰可扫读的布局。
- 背景动效必须克制，不能影响文字可读性。
- 通过演示脚本逐页检查文案、按钮、错误态和加载态。

当前处置状态：

- Phase 3R3 已实现 GPT 式贴边可收起主页侧栏、AI 对话主页、历史对话、侧栏账号入口、输入区资料库浮层入口、文件上传入口、发送后主页对话态、底部输入区、最近学习轻量列表、克制背景信号线和生成课程浮层，未采用后台管理式左侧菜单。
- `/app/library` 已调整为文件库式资料库，生成课程以覆盖当前页面的浮层呈现，避免资料库退回后台流程面板。
- 登录页和注册页已经有独立视觉入口，不再是普通后台登录框；登录页不提供共享演示学生按钮，快速体验通过注册时选择人工智能导论示例课程进入当前用户空间。
- P3.9 已把资料库、课程空间、Studio、画像、AI 辅导、练习、报告和设置统一到贴边工作区侧栏，减少普通路由和主页风格割裂的风险。
- 学习空间已加入上传建课状态轨道、低依据提示、错误恢复和 Demo fallback 标记，用于降低“只有静态成功态”的演示风险。
- Phase 3 收口重设计中的学习操作系统画布、流程轨道和状态信号层已进入课程空间静态壳子；首页已按 AI 对话主页重做，减少卡片墙和后台模板感。
- 已检查 P3R3 `/app` 桌面和移动宽度，当前未发现水平溢出，资料库浮层和生成课程浮层可打开且保持可读；已补查 `/app/library` 生成课程浮层覆盖整个视口。
- 后续 Phase 4 连接真实认证、课程和 AI/RAG 数据时，仍需防止页面退回表格化、卡片墙和后台管理系统风格。

### R-08 Docker 部署失败

Docker Compose 是比赛提交和同学试用的重要入口。部署失败会导致项目难以复现。

控制动作：

- Compose 文件只包含第一版必要服务。
- 服务启动后提供健康检查接口。
- 初始化数据库、迁移、种子数据和前端静态资源流程可重复执行。
- `.env.example` 解释每个变量的用途和安全要求。

### R-09 密钥泄露

密钥泄露会带来费用、隐私和开源安全风险，是发布前必须拦截的问题。

控制动作：

- 提交前运行敏感信息扫描。
- 日志和错误追踪统一脱敏。
- 前端构建产物禁止包含模型 API Key。
- 发现泄露后记录影响范围、轮换时间和修复动作。

### R-10 文档不同步

项目强调中文文档可用，文档滞后会影响协作、测试和答辩准备。

控制动作：

- 功能变化同时更新 README、需求、API、数据库、测试计划和项目看板中的相关条目。
- 里程碑结束前进行文档一致性复核。
- 文档负责人检查是否存在相互矛盾的状态描述。

### R-11 开源协议遗漏

开源协议和第三方依赖说明影响作品发布质量。比赛材料、演示资料和课程内容也需要清楚说明来源。

控制动作：

- 开源前添加项目 LICENSE。
- 梳理主要依赖许可证。
- 对赛题材料、内置课程资料和演示文件写明来源和使用范围。
- 发布包中避免包含无授权的大体量教材或个人资料。

## 4. 跟踪节奏

- 每日开发前快速检查高等级风险是否出现触发信号。
- 每个阶段结束前更新风险等级、触发信号和处置结果。
- 演示脚本冻结前重点复核 R-02、R-03、R-05、R-07、R-08 和 R-09。
- 开源发布前重点复核 R-09、R-10 和 R-11。
