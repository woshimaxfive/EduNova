# EduNova 风险登记册

日期：2026-07-01

## 1. 文档目的

本文档记录 EduNova 需要持续跟踪的项目风险。风险登记册用于发布计划、测试计划和开发复盘，重点覆盖范围、进度、AI 稳定性、资料上传、RAG、多智能体、前端体验、部署、安全、文档和开源合规。

风险等级说明：

- 高：可能直接影响产品发布、主链路演示或开源安全。
- 中：可能影响体验、稳定性或开发效率，需要在迭代中主动控制。
- 低：影响范围有限，通过常规复核即可控制。

## 3. 重点风险处置细则

### R-01 范围膨胀

EduNova 第一版的主线是学生个人学习闭环。任何偏离该主线的功能都需要回答三个问题：是否服务产品演示、是否支撑核心验收、是否能在当前周期稳定完成。不能同时满足时，不进入当前阶段。

控制动作：

- 需求规格作为范围基线。
- 项目看板只放当前阶段可交付任务。
- 对新增想法记录来源、收益和成本，由项目负责人决定是否进入后续版本。

### R-02 时间不足

时间风险通常来自“核心链路未完成但外围功能继续增加”。必须以可演示闭环为优先级排序。

控制动作：

- 每日检查注册登录、课程、上传、RAG、Agent、路径、练习、报告、示例课程和 Docker 的完成状态。
- 优先修复会阻断演示脚本的问题。
- 对非主链路能力采用明确降级，保证使用者能理解能力边界。

### R-03 模型不稳定

AI 能力是项目亮点，也是最大不确定性来源。模型不稳定时，系统要表现为“可解释的降级”，而不是页面卡死或生成虚假内容。

控制动作：

- 所有模型调用设置超时、重试次数和失败原因。
- 结构化输出通过 JSON Schema 或等价校验层检查。
- 模型失败时返回人工可读错误、重试和设置入口。
- 语义路由、权限与统计可保守降级；学生可见路径、资源、练习题面和报告叙事不得用模板伪装模型成功。
- 结构化任务按 Provider 能力关闭不必要思考并限制尝试；只有结构合同失败允许一次定向修订，网络超时不重放大请求。

### R-04 上传解析失败

上传资料自动建课是关键能力。解析失败会直接破坏“学生上传资料形成个人课程”的主线。

控制动作：

- 每种支持格式至少保留一个小型演示样例。
- 后端记录解析阶段、页数、字符数、分块数和错误类型。
- 前端展示上传、解析、建课、索引和可学习状态。
- 对解析失败的文件给出重新上传或转换格式建议。

### R-05 RAG 无引用

RAG 没有引用会削弱可信度，也会影响“可解释学习资源”的实际效果。

控制动作：

- RAG 返回结构必须包含答案、引用列表和资料不足标记。
- 引用列表至少包含资料名称、位置、摘要和分块标识。
- 前端将引用放在答案附近，便于学生核对。
- 评测用例覆盖“有资料命中”和“资料不足”两类场景。

### R-06 多智能体空心化

多智能体不能只停留在名称上，需要体现分工、协作、审查和轨迹。

控制动作：

- 每个 Agent 有固定职责和输入输出边界。
- Agent 轨迹展示任务状态、关键输入摘要、输出摘要和 ReviewAgent 结论。
- 失败时记录失败节点，允许用户重试或降级生成。

### R-07 前端体验不足

前端是用户体验和产品演示的第一感知。体验不足会让已经完成的后端和 AI 能力难以被理解。

控制动作：

- 首页直接进入 AI 学习空间，不做空泛展示页。
- 首屏采用 AI 对话主页：贴边可收起历史侧栏、侧栏账号入口、中心轻量输入、发送后主页对话态、底部输入区、输入区资料库浮层入口、文件上传入口、最近学习轻量列表和生成课程浮层入口。
- 学习画布、资源工坊、证据层和 Agent 轨迹进入回答下方的可展开区域、学习模式或后续资源页，不在首页或课程默认首屏堆满。
- 不采用固定左侧后台菜单、指标卡片堆和普通管理系统布局。
- 上传建课、RAG 问答、学习路径和练习评估都有完整状态反馈。
- 引用、Agent 轨迹和掌握度地图使用清晰可扫读的布局。
- 背景动效必须克制，不能影响文字可读性。
- 通过演示脚本逐页检查文案、按钮、错误态和加载态。

当前处置状态：

- Phase 3R3 已实现 GPT 式贴边可收起主页侧栏、AI 对话主页、历史对话、侧栏账号入口、输入区资料库浮层入口、文件上传入口、发送后主页对话态、底部输入区、最近学习轻量列表、克制背景信号线和生成课程浮层，未采用后台管理式左侧菜单。
- `/app/library` 已调整为文件库式资料库，生成课程以覆盖当前页面的浮层呈现，避免资料库退回后台流程面板。
- 登录页和注册页已经有独立视觉入口，不再是普通后台登录框；登录页不提供共享演示学生按钮，新用户默认空白起步，也可在注册时主动选择《数据结构与算法》内置课程进入自己的学习空间。
- P3.9 已把资料库、课程空间、资源工坊、画像、AI 辅导、练习、报告和设置统一到贴边工作区侧栏，减少普通路由和主页风格割裂的风险。
- P3.15 已补回答附加信息默认折叠、资料选择禁用态、单一生成课程浮层和资源工坊单一主操作，降低按钮误导、浮层叠加和对话主体被附加信息挤占的风险。
- 学习空间已加入上传建课状态轨道、低依据提示、错误恢复和本地预备反馈，用于降低“只有静态成功态”的演示风险；真实数据缺口不能用 demo 内容伪装。
- Phase 6.5 已把课程空间改为默认问答模式 + 按需学习模式，不再常驻知识画布、资源区和证据层；首页已按 AI 对话主页重做，减少卡片墙和后台模板感。
- 已检查 P3R3 `/app` 桌面和移动宽度，当前未发现水平溢出，资料库浮层和生成课程浮层可打开且保持可读；已补查 `/app/library` 生成课程浮层覆盖整个视口。
- 后续接入真实 AI/RAG、资源生成和学习评估数据时，仍需防止页面退回表格化、卡片墙和后台管理系统风格。

### R-08 Docker 部署失败

Docker Compose 是本地试用和发布复现的重要入口。部署失败会导致项目难以复现。

控制动作：

- Compose 文件只包含第一版必要服务。
- 服务启动后提供健康检查接口。
- 初始化数据库、迁移、种子数据和前端静态资源流程可重复执行。
- `.env.example` 解释每个变量的用途和安全要求。

### R-09 密钥泄露

密钥泄露会带来费用、隐私和开源安全风险，是发布前必须拦截的问题。

控制动作：

- 提交前运行敏感信息扫描。
- 日志和错误追踪统一脱敏。
- 前端构建产物禁止包含模型 API Key。
- 发现泄露后记录影响范围、轮换时间和修复动作。

### R-10 文档不同步

项目强调中文文档可用，文档滞后会影响协作、测试和发布准备。

控制动作：

- 功能变化同时更新 README、需求、API、数据库、测试计划和项目看板中的相关条目。
- 里程碑结束前进行文档一致性复核。
- 文档负责人检查是否存在相互矛盾的状态描述。

### R-11 开源协议遗漏

开源协议和第三方依赖说明影响项目发布质量。演示资料和课程内容也需要清楚说明来源。

控制动作：

- 开源前添加项目 LICENSE。
- 梳理主要依赖许可证。
- 对外部材料、内置课程资料和演示文件写明来源和使用范围。
- 发布包中避免包含无授权的大体量教材或个人资料。

### R-12 基础设施迁移与供应链膨胀

Docling 模型制品、观测 SDK、对象存储与安全扫描会增加镜像体积、构建时间和依赖攻击面；第三方升级也可能改变解析或协议行为。

控制动作：

- 第三方能力只通过适配层接入，固定版本并生成直接依赖许可证清单。
- 解析器保留 `legacy` 显式回滚，旧资料不批量重建，重解析失败不覆盖已确认数据。
- Docling 仅进入 AI Worker 镜像；ClamAV、OTLP、Ragas 联网评测均默认关闭并按部署范围启用。
- 使用无版权夹具、OpenAPI 漂移、Provider 错误矩阵、供应链扫描和 Docker E2E 作为升级门禁。
- 每次升级复核许可证、已知漏洞、离线行为、镜像体积、内存和真实项目样例质量。

### R-13 原生搜索与跨会话记忆边界

厂商原生搜索格式可能变化或只返回文本而没有可验证 URL；跨会话索引若隔离条件或删除语义错误，会造成隐私泄露或把历史对话误作课程证据。

控制动作：

- Provider 能力使用白名单注册表，普通兼容地址默认无原生搜索；无可验证 URL 必须回退或警告。
- 搜索只发送必要独立问题，一次回答不默认双路搜索，Provider 原始响应不落库。
- 记忆查询固定当前用户、排除当前会话、相同向量指纹且最多 5 条；关闭立即删除派生索引。
- 历史来源从课程证据、画像、弱点、掌握度和评分消费者中显式排除，并用自动测试锁定。
- LangChain/LangGraph 固定兼容版本，升级前回归 `trim_messages`、ToolNode 输入输出和 Docker Worker。

### R-14 长模型操作超时与个性化稳定性

Phase 28 真实验收中，两次直接后端路径规划约为 53 秒和 62 秒，经 nginx 的一次请求在 60 秒返回 504。两组画像虽产生了学习包类型或顺序差异，但其中一组由确定性 fallback 完成，不能据此声称模型个性化稳定达到验收目标。

控制动作：

- 路径规划、练习生成和报告生成均已接入 AIJob/RQ 的可恢复异步模式；继续监控队列堆积、Worker 版本漂移和外部模型结构化输出稳定性。
- 保留 `doc + mindmap + quiz` 安全 fallback，但 trace 和界面必须明确标注降级，不能把 fallback 冒充模型成功。
- 用固定无版权课程、两组可信画像和同一模型配置继续做低次数对照；至少两项可观察差异且无 fallback 才升级实证状态。
- 性能报告将路径规划与已经达标的 SSE、AIJob、RAG 指标分开记录，禁止用平均值掩盖长尾。

处置更新（Phase 29/36）：路径、练习生成和报告生成的长同步超时根因已通过 AIJob/RQ 消除，旧同步路由仅保留兼容且前端不再调用。任务支持立即入队、托盘进度、刷新恢复、取消、重试和完成后读取持久化结果。外部模型结构化个性化稳定性风险继续保留，不能把 fallback 计为通过。

处置更新（Phase 37）：真实节点审计发现，通用三次重试和二次模型审核会把可选增强放大到 70–140 秒。题目增强与报告叙事现把安全自审合并进首次结构化响应，并分别限制为一次 50/40 秒尝试；不合格内容直接回退证据型题稿或确定性报告。最终代码的 Docker 对照降至 52.65/42.81 秒。两次最终验收均因当前慢 Provider 超时而触发安全 fallback，因此模型成功率风险保留，不能只以耗时达标替代内容质量判断。

处置更新（Phase 31）：真实 Provider 会把示例 schema 包在 `output` 字段并偶发返回非白名单因素代码。当前仅对这一已知包装做确定性解包，随后仍执行完整 Pydantic、任务、资源、模态和权限校验；因素代码取白名单交集，不让未知因素进入持久化或说明。两组可信画像均完成无 fallback 的模型增强路径，同一二叉树遍历任务在教学策略和资源模态上出现两项可观察差异。手动更新路径现与练习重排一样保留已完成进度。结构化输出风险降为中，安全 fallback 继续保留。

### R-15 国内来源可用性误标

服务端可访问境外 URL 不代表中国大陆学生可稳定访问；国内社区可访问也不代表内容权威。

控制动作：来源只标记 `access_scope`，不声明实时可达；排序同时保留相关性与权威性；B站优先、YouTube 仅作境外补充且不进入必学主动作；国际原始规范和论文在问题需要时继续保留。

### R-16 Docling 首次模型制品下载不稳定

AI Worker 首次构建仍需要从 Hugging Face 获取 Docling 布局和表格模型。国内网络、镜像重定向或上游 5xx 可能导致模型层失败；把所有超时无限放大只会延长无反馈等待。

控制动作：使用 BuildKit 持久缓存复用 pip、Torch 和 Hugging Face 制品；模型下载仅做三次有界重试；新镜像完整成功前不替换旧健康镜像；官方端点和镜像端点均需真实验证，失败必须记录为未通过。发布环境可在受控网络提前构建并保存固定镜像，但不得把用户教材、密钥或模型响应放入构建上下文。
