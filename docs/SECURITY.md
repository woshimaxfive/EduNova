# EduNova 安全基线

日期：2026-07-01

## 1. 文档目的

本文档定义 EduNova 第一版的安全边界和实现约束，用于指导账号体系、AI 能力、资料上传、日志、演示模式、开源发布和权限控制。安全目标是保护学生账号、学习画像、上传资料、模型调用密钥和生成内容可信度，同时保证比赛演示环境可部署、可复现、可开源。

适用范围：

- React + TypeScript 前端。
- FastAPI 后端。
- PostgreSQL、pgvector、Redis 和本地文件存储。
- LangGraph 多智能体编排。
- RAG 检索、引用展示和 AI 辅导。
- Docker Compose 本地部署与演示环境。

## 2. 安全原则

1. 默认最小权限，学生只能访问自己的账号、课程、资料、学习记录和生成结果。
2. 账号、密钥、上传资料和 AI 上下文分层隔离，避免跨用户、跨课程、跨环境泄露。
3. AI 输出必须可追溯，涉及资料问答和学习建议时展示引用或资料不足提示。
4. 演示模式只能使用演示数据和演示密钥配置，不能读取真实用户资料。
5. 日志用于定位问题，不记录密码、JWT、API Key、原始上传正文和完整提示词。
6. 开源前必须完成敏感信息扫描和文件清单复核。

## 3. 账号密码

账号密码安全要求：

- 密码只保存强哈希结果，使用带盐的现代密码哈希算法。
- 注册、登录、修改密码接口不得在响应体或日志中返回明文密码。
- 登录失败返回统一错误信息，避免暴露账号是否存在。
- 密码长度、复杂度和错误次数限制由后端统一校验，前端只做交互提示。
- 学生账号默认只能访问学生端能力，`admin` 角色字段仅用于轻量维护和后续扩展。
- 重置密码、修改邮箱、删除账号等高风险操作需要重新验证当前身份。

开发约束：

- 测试数据使用明显的演示账号，不复用个人真实密码。
- 文档、脚本、提交记录和截图中不得出现真实账号密码。
- 数据库种子数据中的密码必须是哈希值或由启动脚本现场生成。

## 4. JWT 与会话

JWT 用于前后端认证时必须满足以下要求：

- JWT 签名密钥只从环境变量读取；`.env.example` 和 Compose 默认值只能用于本地开发，不得用于正式部署。
- Phase 4.1 第一版只实现 Access Token，不实现服务端 token 黑名单和 Refresh Token；退出登录由前端清理 token，后续正式部署前再补刷新与服务端失效策略。
- Token 载荷只包含必要字段，当前为用户标识、签发时间和过期时间。
- Token 不写入 URL，不通过查询参数传递。
- 后端所有受保护接口必须校验签名、过期时间、用户状态和权限范围。
- 用户修改密码、账号禁用和 Refresh Token 失效策略属于后续安全增强，不能影响当前 Phase 4.1 基础闭环的最小可用性。

前端存储要求：

- 优先使用安全的浏览器存储策略，避免把 Token 暴露给第三方脚本。
- 前端请求统一通过 API 客户端附加认证头，避免页面组件自行拼接。
- 认证失败时清理本地登录状态并跳转登录页。
- 前端路由保护只作为体验层约束，不能替代后端鉴权；`/app/*` 页面隐藏不代表数据接口安全。
- Demo 入口进入学习空间时必须和真实用户登录态隔离，不能复用真实用户资料上下文。

## 5. API Key 与外部模型密钥

模型 Provider、Embedding 服务、对象存储和第三方 API 的 Key 按以下规则管理：

- 所有 API Key 只允许通过 `.env`、部署密钥或运行时配置注入。
- `.env`、真实密钥文件、缓存目录和本地上传文件必须被 `.gitignore` 排除。
- `.env.example` 只能提供变量名、用途和安全格式说明，不能出现真实密钥或可用密钥片段。
- 后端启动时检查关键密钥是否存在，并用清晰错误提示说明缺失配置。
- 不在前端打包产物中嵌入模型 API Key，前端只调用后端受控接口。
- 多模型 Provider 使用统一适配层，避免业务代码直接散落密钥读取逻辑。

密钥轮换要求：

- 发现密钥泄露后立即撤销旧密钥、生成新密钥、更新部署配置并复查访问日志。
- 演示环境和开发环境使用不同密钥，避免演示故障影响个人账号或生产额度。
- 日志和错误追踪中只允许显示密钥前后少量脱敏字符。

## 6. 上传资料隔离

用户上传的 PDF、PPTX、DOCX、Markdown、TXT 等资料必须先按用户隔离；资料加入课程、生成课程或进入 RAG 检索后，再按课程关联隔离：

- 文件存储路径包含不可枚举的用户目录，不直接使用原始文件名作为访问路径；加入课程后的派生切片和索引再绑定课程。
- 原始文件名作为元数据保存时需要转义展示，避免脚本注入和路径穿越。
- 上传接口校验文件类型、扩展名、大小、页数或文本长度。
- 解析任务运行在受控目录内，不允许访问项目源码、环境变量文件和其他用户目录。
- 原始资料和解析文本必须绑定 `user_id`；课程内分块、向量索引和生成课程内容绑定 `user_id` 与 `course_id`。
- 同一资料加入多个课程时，只能通过受控关联关系授权，不能因为共用原文件导致跨课程越权读取。
- 删除课程或资料时同步删除原始文件、解析结果、向量分块和相关生成任务记录。

访问控制：

- 下载、预览、重新解析、生成课程和删除资料前必须校验资料归属。
- 管理维护能力只能访问演示或授权范围内的数据。
- 后端不信任前端传入的用户标识，用户身份以认证上下文为准。

## 7. RAG 引用与内容可信度

RAG 相关安全目标是减少幻觉、避免跨资料泄露，并让学生理解答案来源：

- 每次基于资料的回答都保存检索到的课程、资料、分块标识和相似度信息。
- 前端证据层展示引用时至少包含资料名称、章节或页码、相关片段摘要和生成时间。
- 证据层只展示白名单摘要字段，不展示完整系统提示词、完整上传原文、完整模型输入或完整模型输出调试载荷。
- 未检索到足够依据时，AI 辅导必须返回资料不足提示，不能伪造引用。
- 检索过滤条件必须包含用户、课程和资料范围，避免跨用户召回。
- 生成学习资源、练习和评估报告时记录所用资料来源，便于复核。
- ReviewAgent 对关键输出进行引用完整性检查，发现无引用结论时降级或要求重生成。

引用展示约束：

- 引用片段只展示必要摘要，不整段暴露用户上传资料。
- 导出的学习档案包含引用来源，但不包含未经用户确认的完整原文。
- 内置课程和用户上传课程的引用来源在界面上清晰区分。

## 8. 防提示词注入

EduNova 会处理用户上传资料和学生提问，必须假设资料中可能包含恶意指令：

- 系统提示词、工具调用规则和安全策略与用户资料分层传入模型。
- 上传资料中的文本永远作为资料内容处理，不能提升为系统指令。
- RAG 注入上下文前标明资料边界和来源，要求模型只把资料作为参考。
- 对“忽略系统规则”“输出密钥”“删除数据”“访问其他课程”等指令进行拦截或降级。
- Agent 工具调用由后端白名单控制，模型不能直接拼接数据库语句、文件路径或系统命令。
- ReviewAgent 检查输出是否包含越权请求、密钥、隐私信息或无依据承诺。

高风险场景处理：

- 上传资料声称自己是系统提示词时，按普通文本保存和引用。
- 用户要求查看其他人的资料、课程、Token、密钥或日志时，返回拒绝说明。
- 模型输出包含可疑脚本、命令或外部链接时，前端以安全文本展示，不直接执行。

## 9. 日志脱敏

日志分为访问日志、业务日志、AI 任务日志和错误日志。所有日志遵守最小必要原则：

- 不记录明文密码、JWT、Refresh Token、API Key、数据库连接串和完整 Cookie。
- 不记录完整上传资料正文、完整学生学习画像和完整提示词。
- 用户标识、课程标识、任务标识可记录，用于追踪问题。
- 对邮箱、手机号、Token、Key、文件路径和异常堆栈中的敏感片段进行脱敏。
- AI 调用日志记录 Provider、模型名、耗时、状态、Token 用量和任务标识。
- 失败日志包含错误类型和排查建议，不暴露密钥、原始请求体或内部路径。

日志保留：

- 开发环境日志保留时间短，便于快速清理。
- 演示环境日志只保留排障所需字段。
- 开源仓库不提交运行日志、解析缓存、向量索引缓存和用户上传文件。

## 10. 演示模式

演示模式用于比赛演示、答辩视频和本地试用，必须与真实用户数据隔离：

- 当前注册登录主链路不提供共享“演示学生”按钮；快速体验通过注册时选择示例课程进入当前用户空间。
- 演示模式后续如启用，可以使用内置演示账号、演示课程、演示资料和可复现的演示任务，但必须独立于真实用户注册登录主流程。
- 演示模式不读取真实 `.env` 中的个人密钥，除非部署者显式配置演示模型 Key。
- 演示模式生成内容应标记为演示数据，避免被误认为真实学习记录。
- 演示模式的上传入口可以使用小型演示文件，不能默认挂载真实用户上传目录。
- 演示重置操作只清理演示数据，不影响普通用户数据。
- 演示截图和视频不展示真实密钥、真实邮箱、个人文件路径和未脱敏日志。

降级策略：

- 未配置模型 Key 时，演示模式可使用本地演示响应，但必须在界面上标注演示来源。
- 模型服务失败时，返回可解释错误和重试入口，不伪造真实模型调用成功。

## 11. 开源前敏感信息扫描

每次准备公开仓库、打包作品或提交比赛材料前执行以下检查：

1. 检查 `.env`、本地上传目录、数据库导出、模型缓存、向量索引缓存和运行日志是否被提交。
2. 扫描 API Key、JWT、数据库连接串、云服务密钥、邮箱密码和访问 Token。
3. 检查 README、文档、截图、录屏字幕和演示脚本中是否包含真实账号、真实路径或密钥。
4. 检查 `.env.example` 仅包含变量名和安全说明。
5. 检查 Docker 镜像构建过程没有复制本地密钥文件。
6. 检查测试夹具没有使用看起来像真实密钥的字符串。
7. 检查开源协议、第三方依赖许可证和赛题材料引用说明。

推荐命令由仓库脚本统一封装，脚本结果必须在开源前记录到发布说明或验收记录中。

## 12. 权限边界

第一版权限边界以学生端为主，保留轻量维护角色：

| 角色 | 允许能力 | 禁止能力 |
| --- | --- | --- |
| 未登录用户 | 查看公开入口、注册、登录 | 访问课程、上传资料、调用 AI、查看学习记录 |
| 学生 | 管理自己的画像、课程、资料、路径、问答、练习和报告 | 访问其他学生数据、查看密钥、修改系统配置 |
| 轻量维护角色 | 维护演示数据、查看系统健康状态、辅助排查演示问题 | 读取真实用户上传原文、导出他人学习档案、查看明文密钥 |

接口权限要求：

- 所有写操作必须校验登录状态和资源归属。
- 所有读取个人数据的接口必须校验 `user_id` 与认证上下文一致。
- AI 任务启动、轮询、取消和结果读取都需要校验任务归属。
- 管理接口使用独立路由前缀和角色校验，不与学生接口混用。
- 后端返回数据按页面需要裁剪，避免一次返回过量个人信息。

## 13. 安全验收清单

| 检查项 | 验收标准 |
| --- | --- |
| 账号密码 | 密码不明文存储，登录错误不泄露账号存在性 |
| JWT | Token 有过期时间，受保护接口统一校验 |
| API Key | 密钥只来自环境变量，前端包不含密钥 |
| 上传隔离 | 文件、解析文本和向量分块按用户与课程隔离 |
| RAG 引用 | 有依据时展示引用，无依据时提示资料不足 |
| 提示词注入 | 上传资料不能覆盖系统规则，工具调用受白名单约束 |
| 日志脱敏 | 日志不含密码、Token、Key、完整上传正文和完整提示词 |
| 演示模式 | 演示数据与真实数据隔离，降级响应有明确标识 |
| 开源扫描 | 发布前完成敏感信息、许可证和截图复核 |
| 权限边界 | 学生、未登录用户和轻量维护角色权限清晰分离 |
