# EduNova 前端与交互设计基线

日期：2026-07-01

## 1. 设计定位

EduNova 前端第一版不是教育后台，也不是课程管理系统，而是学生每天打开使用的 AI 学习空间。

核心表达：

```text
资料进入系统 -> 形成知识画布 -> AI 对话驱动学习 -> Studio 生成资源
-> 证据层解释引用和 Agent 轨迹 -> 练习评估反哺画像和路径
```

首屏必须让人一眼看出这是一个“学生 AI 学习操作系统”，而不是普通“左侧菜单 + 指标卡片”的管理页面。

登录、注册、Demo 体验、首次进入和路由保护的详细设计见 [FRONTEND_ROUTING_DESIGN.md](FRONTEND_ROUTING_DESIGN.md)。本文档和路由入口设计共同构成 Phase 3A 前端开工基线。

## 2. 参考来源与取舍

| 参考方向 | 借鉴点 | EduNova 取舍 |
| --- | --- | --- |
| ChatGPT | 底部或中心对话入口、自然语言驱动任务 | 将 AI 输入框作为主操作入口，而不是附属客服窗口 |
| NotebookLM | Sources、Chat、Studio 三类结构 | 借鉴资料源和 Studio 输出，不照搬三栏固定布局 |
| Apple 设计语言 | 内容优先、轻材质、层次、克制动效 | 使用柔和玻璃材质和空间层次，避免过度发光 |
| Google Material 3 | 表达性、状态反馈、清晰组件语义 | 借鉴动效和可理解状态，不采用浓重安卓风格 |
| Xiaomi HyperOS | 流动背景、动态玻璃、空间感 | 作为背景动效灵感，正式实现保持安静和可读 |
| Mobbin 教育/AI 产品流 | 真实产品流程、空状态、上传、聊天、学习路径 | 用作交互细节参考，不复制具体界面 |
| Carbon for AI | AI 标识、可解释性、引用和风险提示 | 用于证据层、Agent 轨迹和低依据提示 |

现成 Figma、Dribbble、UI8、Envato 模板只能作为结构参考，不能直接复制视觉、素材或付费模板代码。

### 2.1 Phase 3 收口重设计结论

2026-07-01 的 Phase 3 收口重设计结合 `frontend-design`、`design-taste-frontend`、`ui-ux-pro-max` 和 `redesign-existing-projects` 的规则后，确定 EduNova 不采用通用教育卡片页、紫蓝 AI 渐变页、儿童教育 Claymorphism 或数据密集 Dashboard。

最终方向是：

```text
Productivity Tool + AI-Native UI + Knowledge Graph + Process Map
```

解释如下：

1. **Productivity Tool**：学生每天使用，界面要安静、清晰、可靠，不能像一次性展示页。
2. **AI-Native UI**：AI 命令栏是主入口，但不能把系统退化成纯聊天框。
3. **Knowledge Graph**：知识点网络、路径、薄弱点和资料引用是主视觉，承载赛题辨识度。
4. **Process Map**：上传建课、资源生成和 Agent 协作需要用流程轨道表达，避免长时间白屏和黑箱输出。

需要避免：

- 满屏玻璃拟态。
- 一排排功能卡片。
- 三等分 Bento 卡片墙。
- 紫蓝 AI 光效。
- 儿童教育式彩色软糖风。
- 普通管理后台式指标面板。

EduNova 的签名元素是：

```text
资料流入知识画布，学生通过 AI 命令驱动学习闭环。
```

### 2.2 Phase 3 重定向基线

2026-07-01 与用户连续问答后，Phase 3 首页方向重新收束为：

```text
ChatGPT 式 AI 学习主页 + NotebookLM 资料上下文 + Notion 式课程组织
```

这一方向覆盖首页体验，优先级高于前面“学习画布作为首页主视觉”的旧判断。学习画布、路径、Agent 轨迹和报告仍然重要，但不应该在首页第一屏堆出来，而应进入课程空间或 AI 回答后的可展开过程里。

首页产品规则：

- `/app` 是总 AI 学习入口，不默认进入某一门课程。
- 主页可以有独立历史对话，类似 ChatGPT、Claude、DeepSeek。
- 主页对话可以独立存在，也可以被移入某个课程；移入后从主页历史中消失或标记为已归档。
- 当前课程、学习路径、Agent 链路和报告不在首页抢主视觉。
- 首页主角是“嗨，同学，准备好一起学习了吗？”和中心大输入框。
- 资料库入口放在输入区工具行，默认通过浮层打开，不常驻占用右侧大面积。
- 下方显示 2-3 个最近课程或最近学习空间，参考 OpenMAIC 首页“主入口在上、课程发现/最近课程在下”的结构。
- 引用来源、联网来源、学习路径建议和 Agent 过程出现在 AI 回答下方，可展开查看。

资料与课程规则：

- 资料库是独立层，资料上传后先进入用户资料库，不强制属于某一课程。
- 资料可以作为主页对话的参考，也可以加入已有课程。
- 多份资料可以被选择后生成一门课程。
- 同一份资料可以被多个课程引用；实现上优先使用关联关系，不应复制私有文件原文。
- 生成课程使用完整浮层或上层任务页面，背景变暗，流程包括选择资料、填写课程名称、识别章节和知识点、生成路径和练习、进入课程对话。

输入框工具规则：

- 第一版主输入框至少支持上传资料、选择资料、生成课程入口。
- 联网搜索、语音输入、深入推理可以先作为工具位设计，真实能力按后续阶段接入。
- 不要把这些能力做成首页功能卡片。

## 3. 设计原则

1. 学生学习优先：打开后直接进入学习空间，不做营销首页。
2. 对话驱动：AI 输入框是首页主入口，学生通过自然语言上传资料、生成课程、提问、复习和规划。
3. 画布进入课程：当前课程、知识点、资料、任务、资源和薄弱点在课程空间或回答展开区表达，而不是堆在首页。
4. 证据渐进展开：引用来源、Agent 轨迹、审核状态和置信度默认收在回答下方或侧边抽屉，用户需要时展开。
5. Studio 生成资源：讲解、练习、思维导图、复盘报告、PPT 大纲统一放入课程空间或 Studio 输出区。
6. 华丽但克制：允许轻材质、微动效和空间感，禁止满屏粒子、强发光、紫蓝 AI 渐变和装饰性光球。
7. 真实可实现：所有设计都必须能用 React、CSS、Motion、React Flow、ECharts 等技术落地。
8. 比赛可解释：界面不仅好看，还要能证明多智能体、RAG 引用、上传建课和学习闭环。

## 4. 首屏结构

第一版主工作区采用以下结构，Phase 3 重定向后以“AI 学习对话主页”为准：

```text
顶部轻导航
  EduNova / 学习空间 / 资料库 / Studio / 画像 / 辅导 / 练习 / 报告 / 设置 / 搜索 / 上传 / 用户

左侧或折叠区
  主页历史对话 / 已归档到课程的提示 / 新建对话

中央主区域
  AI 学习输入 / 上传资料 / 选择资料 / 生成课程 / 回答区

输入区工具行或抽屉
  上传资料 / 打开资料库 / 生成课程 / 联网搜索 / 深度思考 / 语音

下方轻量区域
  最近课程 / 最近学习空间 / 内置人工智能导论入口

回答下方展开
  引用来源 / 联网来源 / 学习路径建议 / Agent 过程 / Studio 输出
```

明确不采用：

- 固定左侧后台菜单。
- 首页大面积 KPI 卡片。
- 三列指标仪表盘。
- 把 AI 助手做成普通右下角客服。
- 纯营销落地页。
- 五张并排状态卡。
- 所有模块都使用相同玻璃卡片外观。

## 5. 页面与信息架构

| 页面或区域 | 作用 | 设计要求 |
| --- | --- | --- |
| 学习主页 | 第一屏主体验 | AI 对话主页 + 历史对话 + 输入区资料库浮层入口 + 最近学习轻量列表 |
| 资料库 | 管理独立资料和课程资料关联 | 支持资料作为主页参考、加入课程或生成课程，不做文件表格后台 |
| 课程空间 | 某一课程的深度学习区 | 课程对话 + 学习画布 + Studio + 证据层 |
| Studio | 生成和查看学习资源 | 类似 NotebookLM Studio，但围绕课程学习和评估闭环 |
| 报告 | 查看画像、掌握度、薄弱点和学习档案 | 用可视化和证据链解释推荐原因 |
| 对话画像 | 通过聊天建立和更新画像 | 可以作为首登流程，也可作为学习空间里的模式 |
| 上传建课 | 上传 PPT/PDF/DOCX/Markdown/TXT 并生成课程 | 重点展示“资料变成课程”的阶段动画和进度 |
| AI 辅导 | 课程上下文问答和苏格拉底追问 | 可在学习空间内打开，也可进入沉浸式会话 |
| 练习评估 | 出题、作答、批改、错因复盘 | 和知识画布、复习队列联动 |
| 设置 | 模型 Key、个人信息、导出数据 | 保持轻量，不扩展为复杂后台 |

## 6. 核心交互流程

### 6.1 内置课程学习

```text
进入学习空间
-> 在主页选择人工智能导论或最近课程
-> 进入对应课程空间
-> 点击或询问某个知识点
-> 生成讲解、练习和路径
-> 查看引用与 Agent 轨迹
-> 完成练习
-> 掌握度和复习队列更新
```

### 6.2 上传资料建课

```text
拖入 PPT/PDF/DOCX/Markdown/TXT
-> 文件进入资料库
-> 解析阶段可见
-> 选择作为主页对话参考、加入已有课程或生成新课程
-> 抽取章节和知识点
-> 写入课程向量索引
-> 进入课程空间
-> Studio 推荐可生成资源
```

### 6.3 AI 命令栏

命令栏支持自然语言和附件：

```text
上传这份 PPT 并生成复习课程
根据反向传播给我出 10 道期末题
解释我为什么链式法则总错
把今天的学习整理成复盘报告
生成 7 天期末冲刺计划
```

命令栏不是简单聊天框，它会触发课程、资料、资源、路径、辅导和报告等不同能力。

## 7. 视觉系统

### 7.1 色彩

基础色：

- 背景：冷银白、雾灰、浅银。
- 文字：深墨蓝或深墨色。
- 主强调色：青绿色。
- 学习路径色：少量蓝色，只用于路径、焦点和交互反馈。
- 辅助强调：少量琥珀、珊瑚、草绿，用于状态和风险。

Phase 3 收口建议 token：

```text
背景：#F7FAFA
柔和背景：#EEF4F2
主文字：#101820
弱文字：#62706D
主强调：#087F73
路径蓝：#246BFE
低依据琥珀：#B7791F
错误珊瑚：#D75A4A
边框：rgba(16, 24, 32, 0.12)
```

禁止：

- 大面积紫蓝 AI 渐变。
- 彩虹渐变。
- 满屏强发光。
- 所有组件都使用同一色相导致单调。

### 7.2 材质

允许：

- 轻量玻璃材质。
- 细边框高光。
- 低对比阴影。
- 背景微纹理。
- 低透明度动态光带。

约束：

- 文本区域必须可读。
- 玻璃效果不能覆盖核心信息。
- 背景动画不能抢过学习内容。
- 支持 `prefers-reduced-motion` 降低动效。

### 7.3 排版

- 使用现代无衬线中文字体栈。
- 主标题简短，避免营销口号。
- 功能标签和按钮文案使用学生能理解的中文。
- 页面不使用过多英文装饰词。
- 不用大段说明文字占据首屏。

## 9. 状态设计

每个关键流程必须包含：

- 空状态：告诉学生下一步可以做什么。
- 加载状态：展示具体阶段，而不是普通转圈。
- 进度状态：上传、解析、索引、生成、审核各阶段可见。
- 错误状态：说明原因和下一步，例如重新上传、换格式、稍后重试。
- 低依据状态：资料不足时明确提示，不伪造引用。
- Demo fallback 状态：演示兜底内容必须标记来源。

## 10. 动效策略

第一版动效服务于理解，不为了炫技。

必须有：

- 上传资料进入资料库的过渡。
- 解析阶段进度变化。
- 知识点状态变化。
- Agent 轨迹逐步出现。
- Studio 输出生成完成反馈。

可以有：

- 背景轻微流动。
- 节点悬停和聚焦。
- 证据层滑出。
- 命令栏输入后的任务展开。

禁止：

- 强制长动画阻碍操作。
- 每个元素都漂浮。
- 背景持续高亮闪烁。
- 影响文字可读性的运动。

## 11. 响应式要求

第一版重点支持桌面端比赛演示和普通笔记本屏幕。

最低要求：

- 1440x900 下首屏完整、美观、可演示。
- 1366x768 下主要入口不遮挡。
- 390px 移动宽度下核心内容可读，主页历史、资料库和最近课程允许折叠进按钮或抽屉。
- 按钮文字不溢出，长中文自动换行或省略。

## 12. 测试与验收

Phase 3 前端设计验收标准：

1. 代码实现前先有本文档作为设计基线。
2. 正式前端不得使用固定左侧后台菜单作为主布局。
3. 首页首屏必须以 AI 学习对话和资料入口为主，不默认进入某一课程。
4. 主页必须支持历史对话、上传资料、选择资料、生成课程和最近课程入口。
5. 课程空间或 AI 回答下方必须能承载 RAG 引用、Agent 过程、学习路径建议和资源生成入口。
6. 背景动效克制，不能影响学习内容可读性。
7. 组件具备空状态、加载状态、错误状态和低依据提示。
8. 通过浏览器截图检查桌面和移动宽度布局。
9. 前端构建和基础测试通过。
10. 登录页、注册页、Demo 入口、首次进入引导和路由保护符合 [FRONTEND_ROUTING_DESIGN.md](FRONTEND_ROUTING_DESIGN.md)。
11. P3.7 起，页面上可见的核心按钮不能保持空点击状态；未接真实 API 的能力必须给出本地演示态反馈，并明确后续接入边界。

### 13.1 当前实现说明
