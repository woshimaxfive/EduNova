# EduNova 前端与交互设计基线

日期：2026-07-01

## 1. 设计定位

EduNova 前端第一版不是教育后台，也不是课程管理系统，而是学生每天打开使用的 AI 学习空间。

核心表达：

```text
资料进入系统 -> 形成知识画布 -> AI 对话驱动学习 -> 资源工坊生成资源
-> 证据层解释引用和 Agent 轨迹 -> 练习评估反哺画像和路径
```

首屏必须让人一眼看出这是一个“学生 AI 学习操作系统”，而不是普通“左侧菜单 + 指标卡片”的管理页面。

登录、注册、示例课程体验、首次进入和路由保护的详细设计见 [FRONTEND_ROUTING_DESIGN.md](FRONTEND_ROUTING_DESIGN.md)。本文档和路由入口设计共同构成 Phase 3A 前端开工基线。

## 2. 参考来源与取舍

| 参考方向 | 借鉴点 | EduNova 取舍 |

| NotebookLM | Sources、Chat、资源工坊三类结构 | 借鉴资料源和资源输出，不照搬三栏固定布局 |

### 2.1 Phase 3 收口重设计结论

2026-07-01 的 Phase 3 收口重设计结合 `frontend-design`、`design-taste-frontend`、`ui-ux-pro-max` 和 `redesign-existing-projects` 的规则后，确定 EduNova 不采用通用教育卡片页、紫蓝 AI 渐变页、儿童教育 Claymorphism 或数据密集 Dashboard。

最终方向是：

```text
Productivity Tool + AI-Native UI + Knowledge Graph + Process Map
```

解释如下：

1. **Productivity Tool**：学生每天使用，界面要安静、清晰、可靠，不能像一次性展示页。
2. **AI-Native UI**：AI 命令栏是主入口，但不能把系统退化成纯聊天框。
3. **Knowledge Graph**：知识点网络、路径、薄弱点和资料引用是主视觉，承载赛题辨识度。
4. **Process Map**：上传建课、资源生成和 Agent 协作需要用流程轨道表达，避免长时间白屏和黑箱输出。

需要避免：

- 满屏玻璃拟态。
- 一排排功能卡片。
- 三等分 Bento 卡片墙。
- 紫蓝 AI 光效。
- 儿童教育式彩色软糖风。
- 普通管理后台式指标面板。

EduNova 的签名元素是：

```text
资料流入知识画布，学生通过 AI 命令驱动学习闭环。
```

### 2.2 Phase 3 重定向基线

2026-07-01 与用户连续问答后，Phase 3 首页方向重新收束为：

```text
ChatGPT 式 AI 学习主页 + NotebookLM 资料上下文 + Notion 式课程组织
```

这一方向覆盖首页体验，优先级高于前面“学习画布作为首页主视觉”的旧判断。学习画布、路径、Agent 轨迹和报告仍然重要，但不应该在首页第一屏堆出来，而应进入课程空间或 AI 回答后的可展开过程里。

首页产品规则：

- `/app` 是总 AI 学习入口，不默认进入某一门课程。
- 主页可以有独立历史对话，类似 ChatGPT、Claude、DeepSeek；桌面端侧栏贴浏览器左边缘并可收起。
- 主页对话可以独立存在，也可以被移入某个课程；移入后从主页历史中消失或标记为已归档。
- 当前课程、学习路径、Agent 链路和报告不在首页抢主视觉。
- 首页主角是“嗨，同学，准备好一起学习了吗？”和中心轻量输入框；第一次发送后进入对话态，输入区移动到下方。
- 资料库入口放在输入区工具行，默认通过浮层打开，不常驻占用右侧大面积；浮层显示资料库所有文件，默认未选中，点选后才高亮作为本次对话参考。
- 下方显示 2-3 个最近课程或最近学习空间，参考 OpenMAIC 首页“主入口在上、课程发现/最近课程在下”的结构。
- 引用来源、联网来源、学习路径建议和 Agent 过程出现在 AI 回答下方，可展开查看。

资料与课程规则：

- 资料库是独立层，资料上传后先进入用户资料库，不强制属于某一课程。
- 资料可以作为主页对话的参考，也可以加入已有课程。
- 多份资料可以被选择后生成一门课程。
- 同一份资料可以被多个课程引用；实现上优先使用关联关系，不应复制私有文件原文。
- 生成课程使用完整浮层或上层任务页面，背景变暗，流程包括选择资料、填写课程名称、识别章节和知识点、生成路径和练习、进入课程对话。

输入框工具规则：

- 第一版主输入框至少支持上传资料文件、选择资料、生成课程入口。
- 联网搜索、语音输入、深入推理是主页输入区工具位：联网和深思必须有明确激活态并进入发送 payload，语音入口靠近发送按钮，语音能力使用浏览器 Web Speech API，不上传音频。
- 主输入框采用 Enter 发送、Shift+Enter 换行，贴近成熟 AI 对话产品习惯。
- 不要把这些能力做成首页功能卡片。

### 2.3 P3.11 前端本地功能闭环

P3.11 的目标不是继续扩张页面数量，而是让现有页面在接入真实 API 前已经像一个可用产品：

- 课程空间：课程内输入支持 Enter 发送、Shift+Enter 换行，发送后写入当前课程的真实会话历史，并保留回答引用。
- 资源工坊：学生能选择知识点和资源类型，点击后生成本地队列与资源输出；初始状态不展示假资源。
- 学习画像：学生能编辑学习目标、回答画像问题，并看到画像证据与可信度变化。
- 练习和报告：提交练习后出现本地批改态，导出报告后出现准备态，避免按钮空点击。
- 设置：Phase 6.1 后模型供应商配置改为真实读取、保存和测试连接；讯飞星火 Spark 作为首位 Provider 预设；深度思考和联网搜索不放在设置页，只保留在对话输入区作为运行期工具位。
- 侧栏和命令栏：共享入口优先使用真实跳转、选中态、禁用态或局部内容变化表达；暂未接索引、上传或 AI 服务的入口不再额外弹出全局提示条。

这些状态都必须保持克制，不把“等待 API 接入”的说明直接堆在页面上。能用按钮激活态、局部文本变化、列表刷新或详情面板表达的，不再新增解释卡片或横向提示条。

### 2.4 P3.12 主页对话体验精修

P3.12 开始把重心从“页面都有骨架”转向“主页真的像一个成熟 AI 学习入口”：

- 主页发送问题后，左侧历史必须立即新增该问题并高亮当前会话，给用户稳定的会话持久感。
- 当前主页会话内的连续追问必须继续追加到同一条历史，不允许每发送一次就新建一条左侧会话。
- 侧栏历史搜索必须能直接筛选本地历史，不只弹出提示。
- 桌面端主页采用固定视口结构：浏览器整页不随消息拉长，左侧历史列表内部滚动；右侧主区域负责对话滚动，滚动条位于右侧主区域边缘，消息正文保持可读限宽，输入区始终留在底部。
- 首页允许出现少量快捷学习建议，但必须是轻量按钮，不做卡片墙，也不抢主输入框。
- AI 回答下方必须能渐进展开来源、学习路径和思考过程摘要，模拟后续 RAG、路径生成和 Agent 轨迹接入位置。
- 回答附加信息只做轻量信息层，不做大面积卡片，不在首页铺知识画布。
- 这些内容仍是本地演示态，真实引用、真实路径和真实 Agent 执行记录在后续 API 接入时替换。

### 2.5 P3.13 F12 与开源参考后的结构修正

2026-07-02 再次参考 ChatGPT、Claude、assistant-ui、Vercel AI Chatbot 和 AI Elements 后，EduNova 前端结构继续收紧：

- 桌面端采用固定视口应用壳：左侧贴边侧栏固定高度并由历史列表内部滚动，右侧主区域自己滚动，浏览器整页不能被多轮消息撑长。
- 主页对话输入区保持底部可见，消息正文限宽，右侧滚动条应位于右侧主区域边缘，而不是只在中间窄列出现。
- 普通路由继续复用贴边侧栏，但路由主区域只保留短标题，不展示重复小标题和解释句；具体页面区域自己承担语义名称，`PageFrame` 不抢占“资料库/学习画像/学习报告”等可访问区域名。
- 从普通路由点击“新建对话”必须回到 `/app`，不能只弹提示。
- 资料库上传只把文件加入独立资料库，不自动加入生成课程选择；主页资料库和资料库页生成课程浮层都必须默认未选中，点选后才高亮。
- `/app/library` 的主按钮文案使用“生成课程”，弹层标题保留“从资料生成课程”，让页面层更干净、任务层更明确。
- 资料库浮层必须支持搜索过滤，并保持文件库式列表，不使用“课程内置”这类关系字段替代文件类型。

### 2.6 课程空间双模式决策

2026-07-04 重新对齐赛题和当前前端体验后，课程空间确定为“双模式”方向，详细设计见 [COURSE_SPACE_DESIGN.md](COURSE_SPACE_DESIGN.md)。

```text
默认问答模式：课程版 ChatGPT，AI 对话居中，引用、资源、路径和思考过程在回答下方按需展开
课程内容模式：按需进入章节目录、知识点概览或知识图谱，AI 辅导使用覆盖式抽屉
```

这一决策修正了早期“课程空间常驻三栏展示所有能力”的倾向。课程空间要成为赛题主战场，但默认仍保持对话主导，不把知识画布、资源生成、Agent 轨迹、画像和报告全部堆在第一屏。

2026-07-11 桌面工作区重做后按以下规则落地：

- `/app/courses/:courseId` 默认进入问答模式。
- 无消息时显示推荐问题和开始提问引导，不显示固定 AI 示例回答。
- 有消息时只渲染真实课程消息、真实引用和真实检索状态。
- 每条持久化回答拥有自己的来源、资源、路径、练习、报告和协作轨迹，附件默认折叠且不能串到最新回答。
- A3 八步状态和弱点队列进入覆盖式“学习进度”抽屉，不再常驻首屏。
- 课程栏和进度抽屉中的百分比统一表示知识点平均掌握度；A3 八步保留独立状态，不把步骤完成数包装成学习百分比。
- 打开学习进度抽屉时立即同步学习状态、掌握度、资源、路径和报告；同步保留已有内容，部分失败只显示局部 warning 并允许重试。
- 课程内容按章节组织知识点，默认打开第一个知识点，并可切换概览和 React Flow 图谱。
- AI 辅导默认关闭，以覆盖抽屉服务当前知识点，不压缩课程正文。
- 左侧课程历史固定，主滚动条位于浏览器最右侧，课程输入框固定在主区域底部。
- 切换模式、切换知识点、切换历史不弹中间横向提示条，依靠选中态和结构变化表达。

## 3. 设计原则

1. 学生学习优先：打开后直接进入学习空间，不做营销首页。
2. 对话驱动：AI 输入框是首页主入口，学生通过自然语言上传资料、生成课程、提问、复习和规划。
3. 课程双模式：课程空间默认对话主导，需要深入时进入课程内容，当前课程、知识点、资料、任务、资源和薄弱点在逐回答附件、进度抽屉或课程内容中表达，而不是堆在首页。
4. 证据渐进展开：引用来源、Agent 轨迹、审核状态和置信度默认收在回答下方或侧边抽屉，用户需要时展开。
5. 资源工坊生成资源：讲解、练习、思维导图、代码实操、PPT、动画图解使用共用 `ResourceRenderer`，在课程空间或资源工坊直接交互。
6. 文案克制：页面只保留学生完成任务需要的文字，不把设计思路、接口接入说明或重复小标题写进界面。
7. 华丽但克制：允许轻材质、微动效和空间感，禁止满屏粒子、强发光、紫蓝 AI 渐变和装饰性光球。
8. 真实可实现：所有设计都必须能用 React、CSS、Motion、React Flow、ECharts 等技术落地。
9. 比赛可解释：界面不仅好看，还要能证明多智能体、RAG 引用、上传建课和学习闭环。

## 4. 首屏结构

第一版主工作区采用以下结构，Phase 3 重定向后以“AI 学习对话主页”为准：

```text
贴左边缘侧栏
  EduNova / 资料库 / 资源工坊 / 主页历史对话 / 新建对话 / 搜索历史 / 个人资料 / 设置 / 退出登录 / 可收起按钮

中央主区域
  AI 学习输入 / 上传资料 / 选择资料 / 生成课程 / 回答区

输入区工具行或抽屉
  上传资料文件 / 打开资料库 / 生成课程 / 联网搜索激活态 / 深度思考激活态 / 语音 / Enter 发送

下方轻量区域
  最近课程 / 最近学习空间 / 内置人工智能导论入口

发送后
  主页对话流 / 下方固定输入区

回答下方展开
  引用来源 / 联网来源 / 学习路径建议 / Agent 过程 / 资源输出
```

明确不采用：

- 固定左侧后台菜单。
- 首页大面积 KPI 卡片。
- 三列指标仪表盘。
- 把 AI 助手做成普通右下角客服。
- 纯营销落地页。
- 五张并排状态卡。
- 所有模块都使用相同玻璃卡片外观。

## 5. 页面与信息架构

| 页面或区域 | 作用 | 设计要求 |
| --- | --- | --- |
| 学习主页 | 第一屏主体验 | AI 对话主页 + 历史对话 + 侧栏账号入口 + 输入区资料库浮层入口 + 最近学习轻量列表 |
| 资料库 | 管理独立资料和课程资料关联 | 文件库式列表，支持搜索、查看引用、作为主页参考、加入课程或生成课程，不做后台管理器 |
| 课程空间 | 某一课程的深度学习区 | 默认课程问答，来源/资源/路径/协作轨迹按回答展开；知识点进入课程内容，闭环进入学习进度抽屉 |
| 资源工坊 | 生成和查看学习资源 | 左侧成果库、中央资源画布和右侧覆盖抽屉组成桌面成果工作台，优先保证多模态内容宽度 |
| 报告 | 查看画像、掌握度、薄弱点和学习档案 | 用可视化和证据链解释推荐原因 |
| 对话画像 | 通过聊天建立和更新画像 | 可以作为首登流程，也可作为学习空间里的模式 |
| 上传建课 | 上传 PPT/PDF/DOCX/Markdown/TXT 并生成课程 | 重点展示“资料变成课程”的阶段动画和进度 |
| AI 辅导 | 在当前课程空间问答 | 不设独立中转页，课程行动入口直接聚焦提问输入框 |
| 练习评估 | 出题、作答、批改、错因复盘 | 和知识画布、复习队列联动 |
| 设置 | 模型 Key、个人信息、导出数据 | Phase 6.2 已支持多套模型配置：配置列表 + 当前编辑面板，可新建、测试、设默认和删除；模型连接区只放 Provider 预设、Base URL、Key、回答模型和高级向量模型，保持轻量，不扩展为复杂后台或模型超市；Provider 预设收敛为国内常用服务和本地部署入口。Phase 6.4 后，高级向量模型会用于课程知识库 embedding，缺省时使用显式本地 fallback |

## 6. 核心交互流程

### 6.1 内置课程学习

```text
进入学习空间
-> 在主页选择人工智能导论或最近课程
-> 进入对应课程空间
-> 点击或询问某个知识点
-> 生成讲解、练习和路径
-> 查看引用与 Agent 轨迹
-> 完成练习
-> 掌握度和复习队列更新
```

### 6.2 上传资料建课

```text
拖入 PPT/PDF/DOCX/Markdown/TXT
-> 文件进入资料库
-> 解析阶段可见
-> 选择作为主页对话参考、加入已有课程或生成新课程
-> 抽取章节和知识点
-> 写入或懒加载课程知识切片 embedding
-> 进入课程空间
-> 资源工坊推荐可生成资源
```

### 6.3 AI 命令栏

命令栏支持自然语言和附件：

```text
上传这份 PPT 并生成复习课程
根据反向传播给我出 10 道期末题
解释我为什么链式法则总错
生成一个 Python 代码实操案例

```

命令栏不是简单聊天框，它会触发课程、资料、资源、路径、辅导和报告等不同能力。

## 7. 视觉系统

### 7.1 色彩

## 9. 状态设计

每个关键流程必须包含：

- 空状态：告诉学生下一步可以做什么。
- 加载状态：展示具体阶段，而不是普通转圈。
- 进度状态：上传、解析、索引、生成、审核各阶段可见。
- 错误状态：说明原因和下一步，例如重新上传、换格式、稍后重试。
- 低依据状态：资料不足时明确提示，不伪造引用。
- 本地预备反馈：未接真实能力时只允许给出短反馈或空状态，不能伪装成真实课程、真实引用或真实资源。

## 10. 动效策略

第一版动效服务于理解，不为了炫技。

必须有：

- 上传资料进入资料库的过渡。
- 解析阶段进度变化。
- 知识点状态变化。
- Agent 轨迹逐步出现。
- 资源输出生成完成反馈。

可以有：

- 背景轻微流动。
- 节点悬停和聚焦。
- 证据层滑出。
- 命令栏输入后的任务展开。

禁止：

- 强制长动画阻碍操作。
- 每个元素都漂浮。
- 背景持续高亮闪烁。
- 影响文字可读性的运动。

## 11. 响应式要求

第一版重点支持桌面端比赛演示和普通笔记本屏幕。

最低要求：

- 1440x900 下首屏完整、美观、可演示。
- 1366x768 下主要入口不遮挡。
- 390px 移动宽度下核心内容可读，主页历史、资料库和最近课程允许折叠进按钮或抽屉。
- 按钮文字不溢出，长中文自动换行或省略。

Phase 3 前端设计验收标准：

7. 组件具备空状态、加载状态、错误状态和低依据提示。

## 15. Phase 13 前端视觉硬化（2026-07-10）

本轮只调整现有前端的视觉语言、响应式外壳和可访问交互，不新增页面、接口、数据结构或学习能力。

### 15.1 设计系统收口

- 根级 token 补齐强文字色、等宽字体、浮层阴影、三档圆角和焦点环；路径蓝只保留路径语义，主品牌和交互继续使用玉绿色。
- 运行时品牌图标改为同色系玉绿，不再使用青绿到亮蓝的通用 AI 渐变。
- 普通内容表面减少过度玻璃感；强阴影主要保留给 composer、登录表单和抽屉等确有层级的界面。
- 链接、按钮、输入框、文本域、选择框和可聚焦元素必须有统一 `:focus-visible`；主页 composer 使用 `:focus-within` 表达输入焦点。
- 首页与课程主标题使用标准字重和负字距建立层级，避免依赖系统字体无法稳定提供的 820/840 等合成字重。

### 15.2 页面调整

- 登录页在常见桌面宽度下保持标题单行，表单与背景层级更清晰；移动端继续隐藏左侧预览，只保留登录主任务。
- `/app` 降低问候标题尺寸和字重，推荐问题由强 pill 改为较克制的圆角入口，composer 保持首屏唯一高层级表面。
- `/app/library` 的资料列表主体和普通路由标题统一到同一 1080px 内容网格。
- `/app/courses/:courseId` 使用固定课程栏和 820 至 900px 对话正文；A3 摘要与八步状态收进学习进度抽屉，回答附件就地展开，课程内容和 AI 辅导均不挤压默认对话正文。
- 课程闭环页面共用课程级 Query Key；问答、资源、路径、练习、报告和弱点操作完成后主动失效相关缓存，返回课程空间或打开抽屉即可读取最新状态，不使用持续轮询制造伪实时。

### 15.3 移动工作区壳

- `900px` 及以下默认把工作区侧栏收起为 58px 顶部导航条，只显示 EduNova 品牌与展开按钮。
- 展开后使用最大 320px 的覆盖式侧栏抽屉，完整保留资料库、资源工坊、新建对话、历史搜索、真实历史、个人资料、设置和退出登录。
- 导航、主页新建对话或历史选择完成后，紧凑视口自动收起抽屉。
- 首页、普通 `PageFrame` 路由和课程空间复用同一个响应式侧栏状态，不再分别维护三套移动逻辑，也不再把完整桌面侧栏排到主内容底部。

### 15.4 验收基线

- 自动化：前端 23 个测试文件、180 项测试通过；ESLint 零 warning；TypeScript 与 Vite production build 通过。
- 真实浏览器：`agent-browser` 覆盖登录页、学习主页、移动抽屉、资料库入口和课程空间，检查 1440×1000 与 390×844。
- 移动宽度不得水平溢出；折叠顶栏不得遮挡主标题；课程输入区不得遮挡最后一条内容；键盘焦点必须可见。
