# EduNova 前端与交互设计基线

日期：2026-07-01

## 1. 设计定位

EduNova 前端第一版不是教育后台，也不是课程管理系统，而是学生每天打开使用的 AI 学习空间。

核心表达：

```text
资料进入系统 -> 形成知识画布 -> AI 对话驱动学习 -> Studio 生成资源
-> 证据层解释引用和 Agent 轨迹 -> 练习评估反哺画像和路径
```

首屏必须让人一眼看出这是一个“学生 AI 学习操作系统”，而不是普通“左侧菜单 + 指标卡片”的管理页面。

登录、注册、Demo 体验、首次进入和路由保护的详细设计见 [FRONTEND_ROUTING_DESIGN.md](FRONTEND_ROUTING_DESIGN.md)。本文档和路由入口设计共同构成 Phase 3A 前端开工基线。

## 2. 参考来源与取舍

| 参考方向 | 借鉴点 | EduNova 取舍 |
| --- | --- | --- |
| ChatGPT | 底部或中心对话入口、自然语言驱动任务 | 将 AI 输入框作为主操作入口，而不是附属客服窗口 |
| NotebookLM | Sources、Chat、Studio 三类结构 | 借鉴资料源和 Studio 输出，不照搬三栏固定布局 |
| Apple 设计语言 | 内容优先、轻材质、层次、克制动效 | 使用柔和玻璃材质和空间层次，避免过度发光 |
| Google Material 3 | 表达性、状态反馈、清晰组件语义 | 借鉴动效和可理解状态，不采用浓重安卓风格 |
| Xiaomi HyperOS | 流动背景、动态玻璃、空间感 | 作为背景动效灵感，正式实现保持安静和可读 |
| Mobbin 教育/AI 产品流 | 真实产品流程、空状态、上传、聊天、学习路径 | 用作交互细节参考，不复制具体界面 |
| Carbon for AI | AI 标识、可解释性、引用和风险提示 | 用于证据层、Agent 轨迹和低依据提示 |

现成 Figma、Dribbble、UI8、Envato 模板只能作为结构参考，不能直接复制视觉、素材或付费模板代码。

### 2.1 Phase 3 收口重设计结论

2026-07-01 的 Phase 3 收口重设计结合 `frontend-design`、`design-taste-frontend`、`ui-ux-pro-max` 和 `redesign-existing-projects` 的规则后，确定 EduNova 不采用通用教育卡片页、紫蓝 AI 渐变页、儿童教育 Claymorphism 或数据密集 Dashboard。

最终方向是：

```text
Productivity Tool + AI-Native UI + Knowledge Graph + Process Map
```

解释如下：

1. **Productivity Tool**：学生每天使用，界面要安静、清晰、可靠，不能像一次性展示页。
2. **AI-Native UI**：AI 命令栏是主入口，但不能把系统退化成纯聊天框。
3. **Knowledge Graph**：知识点网络、路径、薄弱点和资料引用是主视觉，承载赛题辨识度。
4. **Process Map**：上传建课、资源生成和 Agent 协作需要用流程轨道表达，避免长时间白屏和黑箱输出。

需要避免：

- 满屏玻璃拟态。
- 一排排功能卡片。
- 三等分 Bento 卡片墙。
- 紫蓝 AI 光效。
- 儿童教育式彩色软糖风。
- 普通管理后台式指标面板。

EduNova 的签名元素是：

```text
资料流入知识画布，学生通过 AI 命令驱动学习闭环。
```

## 3. 设计原则

1. 学生学习优先：打开后直接进入学习空间，不做营销首页。
2. 对话驱动：底部 AI 输入框是主入口，学生通过自然语言上传资料、生成课程、提问、复习和规划。
3. 画布承载认知：当前课程、知识点、资料、任务、资源和薄弱点尽量在学习画布中表达，而不是堆成卡片墙。
4. 证据可滑出：引用来源、Agent 轨迹、审核状态和置信度默认弱化，用户需要时从侧边展开。
5. Studio 生成资源：讲解、练习、思维导图、复盘报告、PPT 大纲统一放入 Studio 输出区。
6. 华丽但克制：允许轻材质、微动效和空间感，禁止满屏粒子、强发光、紫蓝 AI 渐变和装饰性光球。
7. 真实可实现：所有设计都必须能用 React、CSS、Motion、React Flow、ECharts 等技术落地。
8. 比赛可解释：界面不仅好看，还要能证明多智能体、RAG 引用、上传建课和学习闭环。

## 4. 首屏结构

第一版主工作区采用以下结构，Phase 3 收口后以“学习操作系统画布”为准：

```text
顶部轻导航
  EduNova / 学习空间 / 资料库 / Studio / 报告 / 搜索 / 上传 / 用户

当前课程状态条
  当前课程 / 学习焦点 / 今日进度 / Demo 或低依据标记

主学习画布
  知识点网络 / 学习路径 / 资料流入 / 薄弱点 / 当前任务

右侧证据面板
  引用来源 / Agent 轨迹 / ReviewAgent 结论 / 低依据提示

上传建课流程轨道
  上传 -> 解析 -> 生成课程 -> 切片 -> 写入索引 -> 规划路径

Studio Dock
  讲解 / 练习 / 思维导图 / 复盘报告 / PPT 大纲

底部 AI 命令栏
  附件 / 自然语言命令 / 快捷建议 / 发送
```

明确不采用：

- 固定左侧后台菜单。
- 首页大面积 KPI 卡片。
- 三列指标仪表盘。
- 把 AI 助手做成普通右下角客服。
- 纯营销落地页。
- 五张并排状态卡。
- 所有模块都使用相同玻璃卡片外观。

## 5. 页面与信息架构

| 页面或区域 | 作用 | 设计要求 |
| --- | --- | --- |
| 学习空间 | 第一屏主体验 | 知识画布 + AI 命令栏 + Studio Dock |
| 资料库 | 管理内置课程和上传资料 | 以资料源、解析状态、引用覆盖度组织，不做文件表格后台 |
| Studio | 生成和查看学习资源 | 类似 NotebookLM Studio，但围绕课程学习和评估闭环 |
| 报告 | 查看画像、掌握度、薄弱点和学习档案 | 用可视化和证据链解释推荐原因 |
| 对话画像 | 通过聊天建立和更新画像 | 可以作为首登流程，也可作为学习空间里的模式 |
| 上传建课 | 上传 PPT/PDF/DOCX/Markdown/TXT 并生成课程 | 重点展示“资料变成课程”的阶段动画和进度 |
| AI 辅导 | 课程上下文问答和苏格拉底追问 | 可在学习空间内打开，也可进入沉浸式会话 |
| 练习评估 | 出题、作答、批改、错因复盘 | 和知识画布、复习队列联动 |
| 设置 | 模型 Key、个人信息、导出数据 | 保持轻量，不扩展为复杂后台 |

## 6. 核心交互流程

### 6.1 内置课程学习

```text
进入学习空间
-> 选择人工智能导论
-> 点击或询问某个知识点
-> 生成讲解、练习和路径
-> 查看引用与 Agent 轨迹
-> 完成练习
-> 掌握度和复习队列更新
```

### 6.2 上传资料建课

```text
拖入 PPT/PDF/DOCX/Markdown/TXT
-> 文件进入资料库
-> 解析阶段可见
-> 抽取章节和知识点
-> 写入向量索引
-> 在学习画布上生成个人课程
-> Studio 推荐可生成资源
```

### 6.3 AI 命令栏

命令栏支持自然语言和附件：

```text
上传这份 PPT 并生成复习课程
根据反向传播给我出 10 道期末题
解释我为什么链式法则总错
把今天的学习整理成复盘报告
生成 7 天期末冲刺计划
```

命令栏不是简单聊天框，它会触发课程、资料、资源、路径、辅导和报告等不同能力。

## 7. 视觉系统

### 7.1 色彩

基础色：

- 背景：冷银白、雾灰、浅银。
- 文字：深墨蓝或深墨色。
- 主强调色：青绿色。
- 学习路径色：少量蓝色，只用于路径、焦点和交互反馈。
- 辅助强调：少量琥珀、珊瑚、草绿，用于状态和风险。

Phase 3 收口建议 token：

```text
背景：#F7FAFA
柔和背景：#EEF4F2
主文字：#101820
弱文字：#62706D
主强调：#087F73
路径蓝：#246BFE
低依据琥珀：#B7791F
错误珊瑚：#D75A4A
边框：rgba(16, 24, 32, 0.12)
```

禁止：

- 大面积紫蓝 AI 渐变。
- 彩虹渐变。
- 满屏强发光。
- 所有组件都使用同一色相导致单调。

### 7.2 材质

允许：

- 轻量玻璃材质。
- 细边框高光。
- 低对比阴影。
- 背景微纹理。
- 低透明度动态光带。

约束：

- 文本区域必须可读。
- 玻璃效果不能覆盖核心信息。
- 背景动画不能抢过学习内容。
- 支持 `prefers-reduced-motion` 降低动效。

### 7.3 排版

- 使用现代无衬线中文字体栈。
- 主标题简短，避免营销口号。
- 功能标签和按钮文案使用学生能理解的中文。
- 页面不使用过多英文装饰词。
- 不用大段说明文字占据首屏。

## 8. 组件基线

| 组件 | 用途 | 实现建议 |
| --- | --- | --- |
| TopNavigation | 顶部轻导航 | 自定义样式 + Radix 菜单能力 |
| LearningCanvas | 学习画布和知识点网络 | React Flow 或自定义 SVG/Canvas |
| CommandBar | AI 命令栏 | 自定义输入组件，支持附件和快捷指令 |
| SourceCluster | 资料源簇 | 展示上传资料、解析状态、引用覆盖 |
| StudioDock | 资源生成 Dock | 底部工具带或横向 Dock，避免卡片墙 |
| EvidenceLayer | 证据层 | 右侧证据面板或可滑出抽屉 |
| AgentTimeline | Agent 轨迹 | 时间线 + 状态 + 耗时 |
| CitationList | 引用来源 | 摘要展示，不暴露过量原文 |
| MasteryVisual | 掌握度可视化 | ECharts 或 React Flow 节点状态 |
| MotionBackground | 背景微动效 | CSS + Motion，默认克制 |

## 9. 状态设计

每个关键流程必须包含：

- 空状态：告诉学生下一步可以做什么。
- 加载状态：展示具体阶段，而不是普通转圈。
- 进度状态：上传、解析、索引、生成、审核各阶段可见。
- 错误状态：说明原因和下一步，例如重新上传、换格式、稍后重试。
- 低依据状态：资料不足时明确提示，不伪造引用。
- Demo fallback 状态：演示兜底内容必须标记来源。

## 10. 动效策略

第一版动效服务于理解，不为了炫技。

必须有：

- 上传资料进入资料库的过渡。
- 解析阶段进度变化。
- 知识点状态变化。
- Agent 轨迹逐步出现。
- Studio 输出生成完成反馈。

可以有：

- 背景轻微流动。
- 节点悬停和聚焦。
- 证据层滑出。
- 命令栏输入后的任务展开。

禁止：

- 强制长动画阻碍操作。
- 每个元素都漂浮。
- 背景持续高亮闪烁。
- 影响文字可读性的运动。

## 11. 响应式要求

第一版重点支持桌面端比赛演示和普通笔记本屏幕。

最低要求：

- 1440x900 下首屏完整、美观、可演示。
- 1366x768 下主要入口不遮挡。
- 390px 移动宽度下核心内容可读，允许简化画布为列表和时间线。
- 按钮文字不溢出，长中文自动换行或省略。

## 12. 测试与验收

Phase 3 前端设计验收标准：

1. 代码实现前先有本文档作为设计基线。
2. 正式前端不得使用固定左侧后台菜单作为主布局。
3. 首屏必须包含顶部轻导航、学习画布、底部 AI 命令栏、Studio 输出入口和证据层入口。
4. 上传建课、RAG 引用、Agent 轨迹、资源生成和学习评估在界面上有明确位置。
5. 背景动效克制，不能影响学习内容可读性。
6. 组件具备空状态、加载状态、错误状态和低依据提示。
7. 通过浏览器截图检查桌面和移动宽度布局。
8. 前端构建和基础测试通过。
9. 登录页、注册页、Demo 入口、首次进入引导和路由保护符合 [FRONTEND_ROUTING_DESIGN.md](FRONTEND_ROUTING_DESIGN.md)。
