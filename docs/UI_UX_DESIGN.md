# EduNova 前端与交互设计基线

日期：2026-07-01

## 1. 设计定位

EduNova 前端第一版不是教育后台，也不是课程管理系统，而是学生每天打开使用的 AI 学习空间。

核心表达：

```text
资料进入系统 -> 形成知识画布 -> AI 对话驱动学习 -> 资源工坊生成资源
-> 证据层解释引用和 Agent 轨迹 -> 练习评估反哺画像和路径
```

首屏必须让人一眼看出这是一个“学生 AI 学习操作系统”，而不是普通“左侧菜单 + 指标卡片”的管理页面。

登录、注册、Demo 体验、首次进入和路由保护的详细设计见 [FRONTEND_ROUTING_DESIGN.md](FRONTEND_ROUTING_DESIGN.md)。本文档和路由入口设计共同构成 Phase 3A 前端开工基线。

## 2. 参考来源与取舍

| 参考方向 | 借鉴点 | EduNova 取舍 |
| --- | --- | --- |
| ChatGPT | 底部或中心对话入口、自然语言驱动任务 | 将 AI 输入框作为主操作入口，而不是附属客服窗口 |
| NotebookLM | Sources、Chat、资源工坊三类结构 | 借鉴资料源和资源输出，不照搬三栏固定布局 |
| Apple 设计语言 | 内容优先、轻材质、层次、克制动效 | 使用柔和玻璃材质和空间层次，避免过度发光 |
| Google Material 3 | 表达性、状态反馈、清晰组件语义 | 借鉴动效和可理解状态，不采用浓重安卓风格 |
| Xiaomi HyperOS | 流动背景、动态玻璃、空间感 | 作为背景动效灵感，正式实现保持安静和可读 |
| Mobbin 教育/AI 产品流 | 真实产品流程、空状态、上传、聊天、学习路径 | 用作交互细节参考，不复制具体界面 |
| Carbon for AI | AI 标识、可解释性、引用和风险提示 | 用于证据层、Agent 轨迹和低依据提示 |

### 2.1 Phase 3 收口重设计结论

2026-07-01 的 Phase 3 收口重设计结合 `frontend-design`、`design-taste-frontend`、`ui-ux-pro-max` 和 `redesign-existing-projects` 的规则后，确定 EduNova 不采用通用教育卡片页、紫蓝 AI 渐变页、儿童教育 Claymorphism 或数据密集 Dashboard。

最终方向是：

```text
Productivity Tool + AI-Native UI + Knowledge Graph + Process Map
```

解释如下：

1. **Productivity Tool**：学生每天使用，界面要安静、清晰、可靠，不能像一次性展示页。
2. **AI-Native UI**：AI 命令栏是主入口，但不能把系统退化成纯聊天框。
3. **Knowledge Graph**：知识点网络、路径、薄弱点和资料引用是主视觉，承载赛题辨识度。
4. **Process Map**：上传建课、资源生成和 Agent 协作需要用流程轨道表达，避免长时间白屏和黑箱输出。

需要避免：

- 满屏玻璃拟态。
- 一排排功能卡片。
- 三等分 Bento 卡片墙。
- 紫蓝 AI 光效。
- 儿童教育式彩色软糖风。
- 普通管理后台式指标面板。

EduNova 的签名元素是：

```text
资料流入知识画布，学生通过 AI 命令驱动学习闭环。
```

### 2.2 Phase 3 重定向基线

2026-07-01 与用户连续问答后，Phase 3 首页方向重新收束为：

```text
ChatGPT 式 AI 学习主页 + NotebookLM 资料上下文 + Notion 式课程组织
```

这一方向覆盖首页体验，优先级高于前面“学习画布作为首页主视觉”的旧判断。学习画布、路径、Agent 轨迹和报告仍然重要，但不应该在首页第一屏堆出来，而应进入课程空间或 AI 回答后的可展开过程里。

首页产品规则：

- `/app` 是总 AI 学习入口，不默认进入某一门课程。
- 主页可以有独立历史对话，类似 ChatGPT、Claude、DeepSeek；桌面端侧栏贴浏览器左边缘并可收起。
- 主页对话可以独立存在，也可以被移入某个课程；移入后从主页历史中消失或标记为已归档。
- 当前课程、学习路径、Agent 链路和报告不在首页抢主视觉。
- 首页主角是“嗨，同学，准备好一起学习了吗？”和中心轻量输入框；第一次发送后进入对话态，输入区移动到下方。
- 资料库入口放在输入区工具行，默认通过浮层打开，不常驻占用右侧大面积；浮层显示资料库所有文件，默认未选中，点选后才高亮作为本次对话参考。
- 下方显示 2-3 个最近课程或最近学习空间，参考 OpenMAIC 首页“主入口在上、课程发现/最近课程在下”的结构。
- 引用来源、联网来源、学习路径建议和 Agent 过程出现在 AI 回答下方，可展开查看。

资料与课程规则：

- 资料库是独立层，资料上传后先进入用户资料库，不强制属于某一课程。
- 资料可以作为主页对话的参考，也可以加入已有课程。
- 多份资料可以被选择后生成一门课程。
- 同一份资料可以被多个课程引用；实现上优先使用关联关系，不应复制私有文件原文。
- 生成课程使用完整浮层或上层任务页面，背景变暗，流程包括选择资料、填写课程名称、识别章节和知识点、生成路径和练习、进入课程对话。

输入框工具规则：

- 第一版主输入框至少支持上传资料文件、选择资料、生成课程入口。
- 联网搜索、语音输入、深入推理可以先作为工具位设计，真实能力按后续阶段接入；联网搜索和深度思考必须有明确激活态，语音入口靠近发送按钮。
- 主输入框采用 Enter 发送、Shift+Enter 换行，贴近成熟 AI 对话产品习惯。
- 不要把这些能力做成首页功能卡片。

### 2.3 P3.11 前端本地功能闭环

P3.11 的目标不是继续扩张页面数量，而是让现有页面在接入真实 API 前已经像一个可用产品：

- 课程空间：课程内输入支持 Enter 发送、Shift+Enter 换行，发送后写入当前课程的真实会话历史，并保留回答引用。
- 资源工坊：学生能选择知识点和资源类型，生成本地队列与资源输出，后续只需替换为真实任务接口。
- 学习画像：学生能编辑学习目标、回答画像问题，并看到画像证据与可信度变化。
- 练习和报告：提交练习后出现本地批改态，导出报告后出现准备态，避免按钮空点击。
- 设置：Phase 6.1 后模型供应商配置改为真实读取、保存和测试连接；讯飞星火 Spark 作为首位 Provider 预设；深度思考和联网搜索不放在设置页，只保留在对话输入区作为运行期工具位。
- 侧栏和命令栏：共享入口必须有 fallback 行为或状态提示，即使暂未接索引、上传或 AI 服务，也不能静默无反应。

这些状态都必须保持克制，不把“等待 API 接入”的说明直接堆在页面上。能用状态条、按钮激活态、局部文本变化表达的，不再新增解释卡片。

### 2.4 P3.12 主页对话体验精修

P3.12 开始把重心从“页面都有骨架”转向“主页真的像一个成熟 AI 学习入口”：

- 主页发送问题后，左侧历史必须立即新增该问题并高亮当前会话，给用户稳定的会话持久感。
- 当前主页会话内的连续追问必须继续追加到同一条历史，不允许每发送一次就新建一条左侧会话。
- 侧栏历史搜索必须能直接筛选本地历史，不只弹出提示。
- 桌面端主页采用固定视口结构：浏览器整页不随消息拉长，左侧历史列表内部滚动；右侧主区域负责对话滚动，滚动条位于右侧主区域边缘，消息正文保持可读限宽，输入区始终留在底部。
- 首页允许出现少量快捷学习建议，但必须是轻量按钮，不做卡片墙，也不抢主输入框。
- AI 回答下方必须能渐进展开来源、学习路径和思考过程摘要，模拟后续 RAG、路径生成和 Agent 轨迹接入位置。
- 回答附加信息只做轻量信息层，不做大面积卡片，不在首页铺知识画布。
- 这些内容仍是本地演示态，真实引用、真实路径和真实 Agent 执行记录在后续 API 接入时替换。

### 2.5 P3.13 F12 与开源参考后的结构修正

2026-07-02 再次参考 ChatGPT、Claude、assistant-ui、Vercel AI Chatbot 和 AI Elements 后，EduNova 前端结构继续收紧：

- 桌面端采用固定视口应用壳：左侧贴边侧栏固定高度并由历史列表内部滚动，右侧主区域自己滚动，浏览器整页不能被多轮消息撑长。
- 主页对话输入区保持底部可见，消息正文限宽，右侧滚动条应位于右侧主区域边缘，而不是只在中间窄列出现。
- 普通路由继续复用贴边侧栏，但路由主区域只保留短标题，不展示重复小标题和解释句；具体页面区域自己承担语义名称，`PageFrame` 不抢占“资料库/学习画像/学习报告”等可访问区域名。
- 从普通路由点击“新建对话”必须回到 `/app`，不能只弹提示。
- 资料库上传只把文件加入独立资料库，不自动加入生成课程选择；主页资料库和资料库页生成课程浮层都必须默认未选中，点选后才高亮。
- `/app/library` 的主按钮文案使用“生成课程”，弹层标题保留“从资料生成课程”，让页面层更干净、任务层更明确。
- 资料库浮层必须支持搜索过滤，并保持文件库式列表，不使用“课程内置”这类关系字段替代文件类型。

## 3. 设计原则

1. 学生学习优先：打开后直接进入学习空间，不做营销首页。
2. 对话驱动：AI 输入框是首页主入口，学生通过自然语言上传资料、生成课程、提问、复习和规划。
3. 画布进入课程：当前课程、知识点、资料、任务、资源和薄弱点在课程空间或回答展开区表达，而不是堆在首页。
4. 证据渐进展开：引用来源、Agent 轨迹、审核状态和置信度默认收在回答下方或侧边抽屉，用户需要时展开。
5. 资源工坊生成资源：讲解、练习、思维导图、代码实操、PPT 大纲统一放入课程空间或资源输出区。
6. 文案克制：页面只保留学生完成任务需要的文字，不把设计思路、接口接入说明或重复小标题写进界面。
7. 华丽但克制：允许轻材质、微动效和空间感，禁止满屏粒子、强发光、紫蓝 AI 渐变和装饰性光球。
8. 真实可实现：所有设计都必须能用 React、CSS、Motion、React Flow、ECharts 等技术落地。
9. 比赛可解释：界面不仅好看，还要能证明多智能体、RAG 引用、上传建课和学习闭环。

## 4. 首屏结构

第一版主工作区采用以下结构，Phase 3 重定向后以“AI 学习对话主页”为准：

```text
贴左边缘侧栏
  EduNova / 资料库 / 资源工坊 / 主页历史对话 / 新建对话 / 搜索历史 / 个人资料 / 设置 / 退出登录 / 可收起按钮

中央主区域
  AI 学习输入 / 上传资料 / 选择资料 / 生成课程 / 回答区

输入区工具行或抽屉
  上传资料文件 / 打开资料库 / 生成课程 / 联网搜索激活态 / 深度思考激活态 / 语音 / Enter 发送

下方轻量区域
  最近课程 / 最近学习空间 / 内置人工智能导论入口

发送后
  主页对话流 / 下方固定输入区

回答下方展开
  引用来源 / 联网来源 / 学习路径建议 / Agent 过程 / 资源输出
```

明确不采用：

- 固定左侧后台菜单。
- 首页大面积 KPI 卡片。
- 三列指标仪表盘。
- 把 AI 助手做成普通右下角客服。
- 纯营销落地页。
- 五张并排状态卡。
- 所有模块都使用相同玻璃卡片外观。

## 5. 页面与信息架构

| 页面或区域 | 作用 | 设计要求 |
| --- | --- | --- |
| 学习主页 | 第一屏主体验 | AI 对话主页 + 历史对话 + 侧栏账号入口 + 输入区资料库浮层入口 + 最近学习轻量列表 |
| 资料库 | 管理独立资料和课程资料关联 | 文件库式列表，支持搜索、查看引用、作为主页参考、加入课程或生成课程，不做后台管理器 |
| 课程空间 | 某一课程的深度学习区 | 课程对话 + 学习画布 + 资源工坊 + 证据层 |
| 资源工坊 | 生成和查看学习资源 | 类似 NotebookLM 资源工坊，但围绕课程学习和评估闭环 |
| 报告 | 查看画像、掌握度、薄弱点和学习档案 | 用可视化和证据链解释推荐原因 |
| 对话画像 | 通过聊天建立和更新画像 | 可以作为首登流程，也可作为学习空间里的模式 |
| 上传建课 | 上传 PPT/PDF/DOCX/Markdown/TXT 并生成课程 | 重点展示“资料变成课程”的阶段动画和进度 |

| 练习评估 | 出题、作答、批改、错因复盘 | 和知识画布、复习队列联动 |

## 6. 核心交互流程

### 6.1 内置课程学习

```text
进入学习空间
-> 在主页选择人工智能导论或最近课程
-> 进入对应课程空间
-> 点击或询问某个知识点
-> 生成讲解、练习和路径
-> 查看引用与 Agent 轨迹
-> 完成练习
-> 掌握度和复习队列更新
```

### 6.2 上传资料建课

```text
拖入 PPT/PDF/DOCX/Markdown/TXT
-> 文件进入资料库
-> 解析阶段可见
-> 选择作为主页对话参考、加入已有课程或生成新课程
-> 抽取章节和知识点
-> 写入或懒加载课程知识切片 embedding
-> 进入课程空间
-> 资源工坊推荐可生成资源
```

### 6.3 AI 命令栏

命令栏支持自然语言和附件：

```text
上传这份 PPT 并生成复习课程
根据反向传播给我出 10 道期末题
解释我为什么链式法则总错
生成一个 Python 代码实操案例
生成 7 天期末冲刺计划
```

命令栏不是简单聊天框，它会触发课程、资料、资源、路径、辅导和报告等不同能力。

## 7. 视觉系统

### 7.1 色彩

基础色：

- 背景：冷银白、雾灰、浅银。
- 文字：深墨蓝或深墨色。
- 主强调色：青绿色。
- 学习路径色：少量蓝色，只用于路径、焦点和交互反馈。
- 辅助强调：少量琥珀、珊瑚、草绿，用于状态和风险。

Phase 3 收口建议 token：

```text
背景：#F7FAFA
柔和背景：#EEF4F2
主文字：#101820
弱文字：#62706D
主强调：#087F73
路径蓝：#246BFE
低依据琥珀：#B7791F
错误珊瑚：#D75A4A
边框：rgba(16, 24, 32, 0.12)
```

禁止：

- 大面积紫蓝 AI 渐变。
- 彩虹渐变。
- 满屏强发光。
- 所有组件都使用同一色相导致单调。

### 7.2 材质

允许：

- 轻量玻璃材质。
- 细边框高光。
- 低对比阴影。
- 背景微纹理。
- 低透明度动态光带。

约束：

- 文本区域必须可读。
- 玻璃效果不能覆盖核心信息。
- 背景动画不能抢过学习内容。
- 支持 `prefers-reduced-motion` 降低动效。

### 7.3 排版

- 使用现代无衬线中文字体栈。
- 主标题简短，避免营销口号。
- 功能标签和按钮文案使用学生能理解的中文。
- 页面不使用过多英文装饰词。
- 不用大段说明文字占据首屏。
- 页面说明、模块小标题和状态提示必须短，避免把原型说明、设计原则或“真实接口接入后”这类开发提示展示给学生。

## 8. 组件基线

| 组件 | 用途 | 实现建议 |
| --- | --- | --- |
| AppSidebar | 受保护应用区贴边侧栏 | 资料库、资源工坊、主页历史、个人资料、设置、退出登录和收起按钮共用同一套工作区外壳；不放“学习空间”重复入口 |
| HomeChat | AI 学习主页 | 贴边可收起主页侧栏、轻量输入框、发送后主页对话流和下方输入区 |

## 9. 状态设计

每个关键流程必须包含：

- 空状态：告诉学生下一步可以做什么。
- 加载状态：展示具体阶段，而不是普通转圈。
- 进度状态：上传、解析、索引、生成、审核各阶段可见。
- 错误状态：说明原因和下一步，例如重新上传、换格式、稍后重试。
- 低依据状态：资料不足时明确提示，不伪造引用。
- Demo fallback 状态：演示兜底内容必须标记来源。

## 10. 动效策略

第一版动效服务于理解，不为了炫技。

必须有：

- 上传资料进入资料库的过渡。
- 解析阶段进度变化。
- 知识点状态变化。
- Agent 轨迹逐步出现。
- 资源输出生成完成反馈。

可以有：

- 背景轻微流动。
- 节点悬停和聚焦。
- 证据层滑出。
- 命令栏输入后的任务展开。

禁止：

- 强制长动画阻碍操作。
- 每个元素都漂浮。
- 背景持续高亮闪烁。
- 影响文字可读性的运动。

## 11. 响应式要求

第一版重点支持桌面端比赛演示和普通笔记本屏幕。

最低要求：

- 1440x900 下首屏完整、美观、可演示。
- 1366x768 下主要入口不遮挡。
- 390px 移动宽度下核心内容可读，主页历史、资料库和最近课程允许折叠进按钮或抽屉。
- 按钮文字不溢出，长中文自动换行或省略。
