## 一句话目标

在 2026 年 7 月 14 日前做出 EduNova 可运行第一版；7 月 15 日到 7 月 20 日完成文档、PPT、演示视频和提交包。

EduNova 第一版要跑通这条主线：

```text
注册登录
-> 对话生成学习画像
-> 选择人工智能导论或上传资料自动建课
-> 多智能体生成 5 类学习资源
-> 生成个性化学习路径
-> RAG 智能辅导答疑
-> 练习评估
-> 更新掌握度、薄弱点和学习报告
-> 展示 Agent 轨迹、引用来源和审核结果
```

## 整体架构

```text
学生网页端
  ↓
FastAPI 后端接口
  ↓
业务服务层：课程、画像、资源、路径、辅导、评估
  ↓
多智能体系统：画像、诊断、检索、资源、路径、辅导、评估、审核
  ↓
大模型 + RAG 知识库 + PostgreSQL + Redis
```

## Phase 0：项目地基

目标：先把项目变成一个规范、可持续开发的仓库。

要做的事：

- 把赛题原文和开发计划纳入 Git 管理。
- 补充编码检查脚本，确保所有文件都是 UTF-8 无 BOM。
- 禁止出现 `\uXXXX` 这种中文转义。
- 补充测试总入口脚本，后面一条命令能跑核心检查。
- 明确哪些文件不能提交，例如 `.env`、缓存、上传文件、虚拟环境、`node_modules`。

为什么重要：

这一步不是功能，但它能防止后面项目变乱。尤其你要开源，编码、忽略文件、环境变量这些一开始就得管住。

## Phase 1：后端和 Docker 地基

目标：让后端项目能启动，数据库和 Redis 能准备好。

要做的事：

- 创建 Python 3.12 虚拟环境。
- 创建 FastAPI 后端项目。
- 添加 `/api/health` 健康检查接口。
- 添加配置文件读取能力，比如数据库地址、Redis 地址、模型 Key。
- 写 Docker Compose 初版，包含 PostgreSQL、Redis、后端、前端、Nginx。

验收标准：

打开后端健康检查接口，能看到系统正常返回。

当前进展：后端健康检查、`.env.example`、Docker Compose、backend/frontend Dockerfile 和 Nginx 统一入口配置已经落地；Compose 服务包含 PostgreSQL、Redis、backend、frontend 和 Nginx。

## Phase 2：数据库模型和内置课程

目标：把系统最重要的数据结构建起来。

要做的事：

- 建用户表、课程表、资料表、知识点表。
- 建学习画像表、画像变化记录表。
- 建学习路径、学习任务、资源生成结果。
- 建 Agent 运行日志。
- 建练习、作答、评估报告、错题复习队列。
- 建模型设置表，后续支持用户自己的 API Key。
- 准备内置“人工智能导论”课程包。

为什么重要：

数据库设计决定后面系统能不能扩展。如果这里偷懒，后面上传建课、多用户、学习报告、开源部署都会很痛苦。

## Phase 3：前端 AI 学习空间骨架

目标：先把用户能看到的产品壳子搭起来，并确保它不是普通后台，而是学生愿意每天打开的 AI 学习空间。

页面包括：

- 登录页
- 注册页
- 学习空间
- 资料库
- 资源工坊
- 对话画像页
- 学习路径页
- AI 辅导页
- 练习评估页
- 学习报告页
- 设置页

界面原则：

- 不做营销首页，打开就是学习工具。
- 不做后台管理式左侧导航和卡片堆；`/app` 主页可以使用 GPT 式贴边侧栏承载主页历史和高频入口。
- 使用贴边可收起主页侧栏、侧栏账号入口、中央 AI 学习输入、历史对话、输入区资料库浮层入口、文件上传入口、发送后下方输入区和最近学习轻量列表；学习画布、资源输出区和证据层进入课程空间或回答下方展开区。
- 看起来像现代 AI 学习空间，不像普通后台管理系统。
- 具体设计基线以 `docs/UI_UX_DESIGN.md` 为准。
- 登录、注册、注册 starter mode、首次进入和路由保护以 `docs/FRONTEND_ROUTING_DESIGN.md` 为准。

路由先按这套搭：

```text
/login          登录页
/register       注册页
/demo           Demo 入口
/app            学习空间
/app/library    资料库
/app/courses/:courseId 课程空间
/app/studio     资源工坊
/app/profile    对话画像
/app/tutor      AI 辅导
/app/practice   练习评估
/app/reports    学习报告
/app/settings   设置
```

登录注册要有三条清晰路径：

```text
普通登录
创建账号
注册时选择空白开始或带人工智能导论示例课程开始
```

首次进入时，如果还没有主页历史、上传资料、最近课程或画像，就显示轻量引导，让用户选择：

```text
先和 EduNova 聊聊学习情况
上传自己的课程资料
从人工智能导论开始
```

## Phase 5：上传资料自动建课

目标：用户可以上传老师课件、电子书、讲义、期末题，然后系统自动生成一门课程。

第一版支持：

- PDF
- PPTX
- DOCX
- Markdown
- TXT

处理流程：

```text
上传文件
-> 提取文本
-> 识别课程名、章节、知识点
-> 切分成知识片段
-> 生成向量
-> 存入知识库
-> 生成课程概览
-> 生成初始学习路径
```

前端要显示进度：

```text
已上传
解析中
识别课程结构
切分知识点
建立知识库
生成学习路径
完成
```

## Phase 6：大模型适配和 RAG 检索

目标：系统不绑定某一个模型，并且回答问题时能引用资料来源。

要做的事：

- 做统一模型接口。
- 支持 OpenAI-compatible 风格接口。
- 以后可接 DeepSeek、通义千问、讯飞星火、Kimi 等。
- 支持用户在设置页填自己的 API Key。
- API Key 不能写进日志，前端也只能脱敏显示。
- 做 RAG 检索，能从课程资料中找到相关片段。

RAG 的意义：

不是让大模型凭空回答，而是先查你的课程资料，再基于资料回答，并显示引用来源。

## Phase 7：对话式学习画像

目标：用户不用填一堆表格，而是通过聊天生成学习画像。

画像 8 个维度：

- 专业背景
- 知识基础
- 学习目标
- 认知风格
- 学习偏好
- 薄弱点
- 学习节奏
- 动机与兴趣

还要记录：

- 哪个维度变了
- 为什么变
- 依据是什么
- 什么时候变的

这样答辩时可以解释：系统不是随便判断学生情况，而是有证据链。

## Phase 8：多智能体资源生成

目标：把赛题最核心的“多智能体协同生成资源”做出来。

多智能体流程：

```text
画像智能体读取学生画像
检索智能体查课程资料
诊断智能体判断薄弱点
资源智能体生成资源
审核智能体检查事实性和质量
保存结果和 Agent 日志
```

至少生成 5 类资源：

- 讲解文档
- 思维导图
- 练习题
- 代码实操案例
- PPT 大纲或视频脚本

每个资源都要展示：

- 引用来源
- 审核状态
- 可信度
- 适配度
- Agent 运行轨迹

## Phase 9：学习路径、掌握度图和薄弱点队列

目标：不只是生成资源，还要告诉学生下一步怎么学。

要做的事：

- 根据画像和知识点生成学习路径。
- 展示今日任务和后续任务。
- 做知识点掌握地图。
- 根据错题和先修关系追溯真正薄弱点。
- 生成复习队列。

例子：

```text
学生做错反向传播
-> 系统发现前置知识可能是链式法则薄弱
-> 推荐先补链式法则
-> 再回到反向传播练习
```

这就是“为什么不会”的能力，比单纯错题本更强。

## Phase 10：AI 辅导、练习和评估

目标：完成学习闭环。

AI 辅导要支持：

- 直接解释模式
- 苏格拉底追问模式
- 期末冲刺模式

练习评估要支持：

- 出题
- 作答
- 批改
- 讲解错题
- 更新掌握度
- 更新薄弱点
- 生成学习报告

学习报告要包括：

- 得分
- 掌握度变化
- 薄弱点
- 画像变化
- 下一步建议
- 证据来源

## Phase 11：期末冲刺和资料对比

目标：增加比赛辨识度，也贴近真实学生需求。

期末冲刺模式：

```text
上传课件、复习资料、历年题
-> 提取高频考点
-> 找出薄弱点
-> 生成 3 天、7 天或 14 天冲刺计划
-> 推荐必刷题和复习资料
```

资料对比功能：

- 找多份资料重复出现的重点。
- 找试卷里出现但课件讲得少的知识点。
- 提取疑似考试重点。
- 生成优先复习顺序。

## Phase 12：演示模式、导出和开源准备

目标：保证比赛演示稳定，并为以后开源做准备。

演示模式：

- 内置演示账号。
- 内置人工智能导论课程。
- 内置样例画像、资源、路径、练习、报告。
- 模型 API 不稳定时，使用明确标记的 fallback 数据。

注意：

fallback 不是造假，而是为了演示稳定。界面里会标记这是演示兜底内容。

导出功能：

用户可以导出自己的学习档案 Markdown，包括画像、路径、资源、错题、报告、引用来源和 Agent 轨迹。

开源准备：

- README
- 架构文档
- 部署文档
- 测试说明
- 开源协议说明
- 答辩问答
- AI Coding 工具使用说明

目标：证明系统真的能跑，不是只在代码里“看起来能跑”。

要跑的检查：

- 前端打包
- 浏览器自动化测试
- Docker Compose 启动
- 编码检查

浏览器验收流程：

```text

查看引用来源

生成学习路径

查看学习报告
导出学习档案
```

还要保存截图，后面写文档、做 PPT、录视频都能直接用。
